# Notes and attachment UI

`NotesPage` exports the complete API-backed notes workspace. Mount inside the existing profile-keyed route outlet, for example `/notes`. It reads `kind=note|historical|person`, `id`, `new=1`, `q`, `typeLabel`, `status`, and `offset` from the query string. New comments also accept `targetType` and `targetId`; their target must resolve before saving or uploading. `initialKind="person"` supports a People route alias. Notes/people links use `/notes`; clinical links use the Test Results, medications, procedures and Sources routes.

The three fixed forms are editable Note, Historical Note (draft → explicitly finished), and Person. Editable entries autosave after 650 ms of inactivity. Typing remains enabled during saves and uploads. The stable client ID and cached saved response preserve the editor instance when the first save updates its URL; in-flight typing and upload state are not remounted. Editable Historical Type and Note-to-historical conversion use `NoteTypeCombobox` with per-profile server suggestions. Search text is a local draft: only selecting an existing choice, explicitly adding a new type, or clearing the chip updates the note form. Exact case-insensitive matches reuse the existing spelling and suppress Add; similar labels remain distinct. The selected type appears as a chip with Edit/Clear. Keyboard arrows, Enter, Escape, IME composition and long-list scrolling are supported; Escape first closes the picker inside conversion without dismissing that modal. Normal saves never finalize. Finish flushes or creates the draft, then sends the entire current form and expected version through the same serialized write lane; it never runs automatically. Save draft and Finish are present from initial creation. A finished entry has no edit/reopen controls; corrections create a new linked draft. Converting a saved freeform note uses the same note ID and the dedicated conversion command. New entries and correction drafts use stable requested IDs, making retries after an uncertain response safe. Conflicting saves preserve the user's form and offer an explicit reload/discard action. Links/backlinks resolve current titles; linked notes can show their current contents inline.

`AttachmentPanel` is shared with clinical details:

```tsx
<AttachmentPanel ownerType="observation" ownerId={result.id} />
```

Props: `ownerType`, `ownerId`, optional `version`, `readOnly`, `disabled`, `additionalOwner`, `onNoteChanged(note)`, `onChanged()`, `onBusyChange(busy)`, `prepareOwner(): Promise<Note>`, and `mutateOwner(action): Promise<void>`. It fetches attachment links, uploads original PDF/PNG/JPEG/WebP/GIF bytes, then associates them with their owner. Person profiles also fetch links owned by their stable person ID via `additionalOwner`, so either supported association is visible. Files can be chosen immediately. The editor creates/saves its draft behind the scenes before uploading, then flushes dirty content and reserves the write lane for each association or metadata change. Each mutation refreshes the parent version without replacing newer text. Caption, body location and event date belong to an attachment link. Unlinking retains original bytes. Finished Historical Notes render preview/download controls only. An unsuccessful upload or pending association prevents finishing until retried or explicitly dismissed. Each association uses a stable requested attachment ID, so a retry after an uncertain response does not create a duplicate link. A known successful association followed by a failed refresh retries only the refresh.

Profile safety: all requests use the shared profile-scoped client. Mutation chains capture the profile prefix at mount, which the client rejects after switching profiles. XHR uploads capture that prefix and abort on unmount. The outer route outlet must be keyed by profile to clear note selection, editor state, previews and pending uploads. The editor marks `data-unsaved-changes="true"` for changed content or pending attachments; the profile picker asks before discarding this work, then changes the selected profile before navigating so the old draft blocker does not run a second time.

Navigation safety: the app uses a data hash router. The editor's `useBlocker` protects internal links, list transitions and browser Back/Forward with one Keep editing / Discard and leave dialog. Changing list search/filter parameters without replacing the current editor does not prompt. The first successful save may canonicalize the URL to the same stable ID without prompting or replacing the editor, even when newer typing remains unsaved. Other entry changes remain protected. A late mutation response cannot navigate back into a departed editor. Closing/reloading the browser uses its normal unsaved-work warning. Unsaved note text stays in component memory; it is never written into localStorage, sessionStorage or browser history state. `node --test app/features/notes/navigation.test.ts` checks Back/Forward cancel/proceed, filter changes, saved-entry navigation and profile-switch bypass using React Router's memory history.

No source files, schema, clinical data, profile fixtures, shared client or navigation are owned by this feature. No clinical sample fallback is rendered when an API request fails or a collection is empty.

`draft-writer.ts` serializes text writes, attachment mutations, conversion and finishing with compare-and-swap versions. An uncertain write retries its original snapshot and identity after inspecting the saved state. Definitive validation rejections permit corrected input; conflicts pause automatic writes and preserve local text. The UI distinguishes SQLite save success from a pending portable-copy flush. No browser persistence stores note content.

Save now / Save draft are disabled when there is no changed form or unresolved write failure, and while a save runs. Each editor owns a distinct form ID, including linked notes. Reverting an untouched new form before autosave does not create an empty entry. Finish and export remain separate actions. Attachment Save details similarly requires changed metadata or an unresolved failure; null and empty optional values compare equally.

Self and People use the same Names editor, separate from Display name. Signup/manual names and explicitly confirmed report names participate in unique exact matching; report-backed names show their evidence and cannot be removed through ordinary editing or history restoration. The current storage remains compatible with `fullName`, `knownNames`, and server-owned `sourceKnownNames`; the UI combines these rather than migrating or discarding old profiles. People retains all unknown profile fields. Legacy full name is recovered from `sourceRelative.realName` or legacy `realName` only when a dedicated `fullName` field is absent; an intentional blank is respected. Familiar label, pronouns, birth/death dates, life status, medical context and blood type are separate fields. Partial dates stay partial, and dates do not silently infer life status. Self is the canonical `person_id=patient` profile, with no outgoing-link picker. Provider/finished notes and People show RelatedNotes comments. Test-series links are distinct from individual-result links.

Saved People also show read-only imported source evidence separately from manually added links. The panel requests distinct sources evidenced for the stable Person ID and shows saved clinical entries only when their evidence has the same exact source-record ID. It refreshes with the saved note version, resets pagination on profile or selection changes, and preserves current reclassification, inactive and unavailable states. Shared source evidence never assigns a clinician/care-team role and is never copied into editable `note_links`.

`CreatableCombobox` owns searchable selection, explicit creation, keyboard handling and viewport placement; `SelectionChip` supplies the shared selected-value presentation. Self and People use it for both manually added and report-confirmed names; confirmed-name chips link to their source reports and omit removal controls. `NoteTypeCombobox` is a single-value adapter. `PeopleTags` is a multiple-value adapter that retains person-tag normalization and limits. The non-Self relationship field uses one value. `NotesPage` passes the existing per-profile tag/relationship aggregates through `personOptions`. Typing does not update the form until explicit selection; these controls share presentation without merging the fields' meaning or persistence rules.

Run `node --test app/features/notes/draft-writer.test.ts app/features/notes/navigation.test.ts` for asynchronous save/attachment races, uncertain retries, validation recovery, conflicts, disposal, initial finishing, profile-field preservation and router guards.

Personal birth/death dates use native date/month pickers and a numeric year field with an explicit precision selector. Opening a more precise picker preserves the existing partial value until a replacement is chosen; choosing a lower precision or Unknown is an explicit edit. Death date is shown only for Deceased and is retained when the field is hidden. Incomplete/invalid dates pause autosave, which resumes once corrected. `partial-date.test.ts` tests precision preservation, status changes and rendered native controls.


Self's Display name field is editable and autosaved. Its canonical value comes from the existing patient person's name; Names used for report matching stay separate. The sidebar, profile switcher, Self detail heading, and linked target labels use that saved name, with a separate Self tag in navigation/detail. People excludes canonical Self from list totals, pagination and Relationship filter suggestions. Blank Self names pause autosave and retain the prior stored name. Versioned API metadata updates the in-memory profile registry after saves, while stale responses cannot revert a newer name. Only an actual profile ID change resets editors, aborts requests or clears PDF previews. Names and note text are not stored in browser storage. A rename does not alter raw sources or create another person.

`node --test app/data/profile.test.ts app/features/notes/note-form.test.ts server/test/self-display-name.test.ts` covers canonical projections, editable name versus legal name, persistence across reopen, linked titles/search, rejected stale/blank/restricted saves, profile isolation, stale API/registry responses, in-flight request preservation and rendered sidebar/switcher labels.


## Patient home, People and exports

`/` opens the canonical Self through `Patient.tsx`; the saved display name and person icon identify it in navigation. People remains a separate route, without note-collection tabs. Older person links under Notes redirect to People; canonical Self links lead home. The underlying versioned person-note storage is retained, so the UI change does not migrate or duplicate any health information.

`person.icon` is a portable symbol identifier or a single emoji grapheme. It uses the same autosave, immutable generations, field restoration and rebuild as other person fields. Self's icon is included in versioned profile metadata so a successful save updates the sidebar without switching identities. No remote images or uploads are involved.

Print / Export is near the top of each actual note and Self. Visit brief and New provider packet share the preview flow; see `server/NOTE-EXPORTS.md` for scope, privacy boundaries and attachment behavior. Other people's profiles do not start a patient-wide export.


The Person icon control opens a searchable Lucide-only grid. Names, upstream tags/categories and local synonyms (such as lotus for Flower 2) support prefix and typo-tolerant search. Exact full names receive the strongest boost. Within each match quality, name matches rank above upstream metadata, followed by supplemental synonyms; repeating a tag does not increase its weight. Categories filter results; icons load locally on demand, with 60 results shown initially. Existing emoji values remain readable and restorable, but the picker only offers installed Lucide icons. New values use `lucide:<name>` to distinguish them from legacy identifiers. Search changes do not save until selection; Escape cancels, and keyboard navigation and responsive placement are retained.

The catalog in `shared/person-icon-catalog.json` records the installed package version and pinned upstream metadata commit/source/license. It contains all 2,081 installed names; 1,817 match upstream metadata directly, while remaining aliases/older names are searchable by name. To update, enumerate the installed dynamic icon imports and join upstream icon JSON metadata by name, retaining provenance and empty metadata for unmatched names. Local synonyms and verified alias mappings live separately in `shared/person-icon-vocabulary.ts`; ranking lives in `shared/person-icon-search.ts`. Add specific descriptions or common direct uses, avoiding broad associations such as "system" or misleading matches such as "breathe" for an air vent. No network lookup occurs during search.

The curated `alarm-check`, `alarm-minus` and `alarm-plus` aliases inherit their corresponding `alarm-clock-*` metadata and synonyms. Results show one entry per mapped icon, preferring its canonical name unless the query matches an alias more closely. Existing alias identifiers still validate, render, remain highlighted and restore unchanged. Tests verify these aliases against the installed components; other unmapped aliases retain their existing behavior.

Self's detail badge occupies the right-hand column alongside the display-name heading. Self navigation continues to open Patient home.

## Record owner and save feedback

Ordinary and personal Historical Notes expose `ownerPersonId`, distinct from a Person note's `personId`. New notes capture the selected owner once. Older notes without ownership metadata remain Self; an ordinary edit, link, conversion, correction draft, restore or filter change cannot reassign a saved note. Ownership is retained in versioned `profile_json.recordOwnerPersonId`, through the existing portable format, without changing old generations or adding a database migration.

Clinical navigation carries one `personId` in the URL. Sidebar navigation defaults to Self; explicit People links and collection filters carry the selected person. `PersonScopeProvider` resolves direct record ownership before displaying content, clears stale comparisons when canonicalizing a link, and shows a periwinkle ownership indicator for another person (and a temporary resolving/error state while actual record ownership is unavailable; default Self list navigation needs no check). The mandatory person pill opens an inline native dropdown beside activity filters; Self is neutral and non-Self uses the selection accent. The header offers View person. People and original source browsing remain shared profile collections; accepted Documents has its own person-scoped tab in Sources. A profile's compact Health records section links to those collections and shows up to three active prescriptions and recent procedures. Shared imported source evidence remains a separate provenance view.

`SaveStatus` is beside Save now / Save draft. Untouched saved forms say **All changes saved**; new forms say **Not saved yet**. Editing, saving, acknowledged autosave/manual save, validation failure, attachment work and portable publication retry have distinct visible states. Relative save time starts only after an acknowledged write in this session; older server timestamps do not falsely imply a recent autosave. The exact time is also available in the title. The same serialized writer handles manual and automatic saves. Saving a draft never finishes history or accepts a clinical import.
