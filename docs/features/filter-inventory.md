# Search and filter inventory

Every routed collection uses the same search-first layout, compact saved-filter pills, and one explicit-save editor. Simple unique filters use `CollectionFilters`; People and Historical notes use the richer repeated-rule editor through `PeopleFilters` and its `CompactFilters` adapter.

## Collection pages

- **People — `/people`**, `src/app/features/notes/NotesPage.tsx`, `PeopleFilters.tsx`: debounced text search (`q`), Tags (any/all/excludes, explicit unknown), Relationship, Life status and Text rules (`filters`, legacy `tag`), plus Active/Inactive (`visibility`). Default Active is a visible pill; deleting it selects All. Saved criteria remain below search. Only one rule can be edited, Save applies that rule, Cancel/Escape discards it, and both leave the panel open until the Filters toggle closes it. Active status uses one positive switch instead of an operator and radio choices. Other rule actions and panel collapse are disabled while editing. URL navigation restores applied rules; drafts never change results. Self is excluded through `excludeSelf=1` before totals/pagination; canonical Self links still open its own page. Self is also excluded from the Relationship option list.
- **Notes — `/notes`**, `src/app/features/notes/NotesPage.tsx`: debounced text search (`q`), an Active/Inactive pill (`visibility`) edited with the positive Active switch, and pagination. Notes and Historical notes remain collection tabs.
- **Historical notes — `/notes?kind=historical`**, same page plus `CompactFilters.tsx`: debounced search and saved multi-row conditions for issuing/personal source, acquisition source, type, personal draft/finished/provider status, exact listed-date bounds and text. Multi-select values include explicit unknown; dates support before/after/inclusive-between. Activity is a peer saved pill. Legacy source/type/status parameters still parse; shared URL helpers reset pagination.
- **Test results — `/tests`**, `src/app/pages/TestResults.tsx`: History/By test tabs, search (`q`), saved provider, Active/Inactive and listed-date filters, history sort and pagination. Filters reset selection/comparison through existing navigation helpers. Sort remains outside the conditions panel. Selected test detail keeps its own date bounds and comparison selection.
- **Prescriptions — `/medications`**, `src/app/pages/ClinicalRecords.tsx`: search and a saved personal Active/Inactive pill, plus pagination. Legacy Not reviewed maps to Inactive. Personal activity is independent of imported provider status. Activate prescriptions temporarily shows Inactive; Done/Skip restores the prior filters, search, pagination and selection from that profile’s navigation entry.
- **Procedures — `/procedures`**, same page: search, saved procedure category/view and Active/Inactive pills, pagination. Search/category/visibility changes clear current selection and pagination.
- **Sources — `/sources`**, `src/app/pages/Sources.tsx`: source-files/retained-records tabs, context-specific search, saved Active/Inactive pill and pagination. Retained-record browsing preserves selected-file scoping in URL state rather than turning it into a general filter condition.

## Embedded search and selection surfaces

- **Measurement comparison**, `src/app/components/MeasurementCharts.tsx`: local search of names and aliases with server pagination inside the Compare picker. Used by Test results; the retained, currently unrouted `Overview.tsx` also references charts.
- **Link picker**, `src/app/features/notes/NoteLinks.tsx`: target-type selector plus search across notes, people and clinical records. Local picker state; choosing a result adds a link through the editor.
- **Provider packet notes**, `src/app/features/notes/NoteExportDialog.tsx`: local note-title search filters checkbox choices; selected notes remain selected while hidden by search. Export mode/contents selectors configure the output rather than the page collection.
- **Person icon chooser**, `src/app/components/PersonIcon.tsx`: local fuzzy name/tag/category search and category selector, with bounded visible results. Selection saves the icon; searching does not.
- **Filter value picker**, `src/app/features/notes/FilterValues.tsx`: searchable checklist reused by People and Historical notes. Searching option labels does not deselect hidden saved values; missing saved values remain visible and removable.

Self (`src/app/pages/Patient.tsx`) has no collection search toolbar; its editor can open the icon and export pickers above. History's saved-state selector, Assistant's saved-chat selector, intake source/review controls and person/date field selects choose an object or edit data rather than filter a collection. They were inspected and are outside this filter redesign.

## Verification

Focused mounted tests cover saved/draft separation, one editor, disabled unchanged/invalid saves, positive Active versus life status, provider/date/category filters, legacy tags, tag operators/unknown/missing values, Escape/focus, URL Back/Forward, malformed/unsupported filters and the 12-builder-rule limit. Historical tests protect explicit saves and date operators. Prescription tests protect the temporary activation snapshot and profile isolation. The server regression checks Self exclusion before count/pagination while preserving direct access and other API consumers, and combines activity with independent life status.

A focused Chromium journey runs against a fresh encrypted fictional profile: apply a rule, verify results/URL, navigate Back/Forward, check Self exclusion and keyboard focus, then capture both editor and pills at desktop/mobile widths in light/dark modes. Optional screenshots use `CRS_PEOPLE_VISUAL_DIR` outside Git. No running preview, Docker build or private archive is needed.

[`collection-filter-rollout.test.ts`](../../src/tests/browser/collection-filter-rollout.test.ts) exercises all six additional collection views against a freshly generated encrypted Placebo profile. `CRS_COLLECTION_FILTER_VISUAL_DIR` enables a 24-image light/dark desktop/mobile matrix outside Git. The integrated component run passed 260 checks; state checks retain source/provider distinctions and navigation behavior. [`prescription-activation-filters.test.ts`](../../src/tests/browser/prescription-activation-filters.test.ts) verifies exact prior-query restoration through the new pills and editor. Existing simple URL fields can each appear once; edit changes that field's value, while Add selects an unapplied field. People/Historical rules remain repeatable conditions with their existing operators and limits.

## Person scope

Notes, Historical notes, Test results (including trends and vision), Prescriptions, Procedures and accepted Documents use a mandatory single-person pill beside Active. It defaults to Self, opens an inline native People dropdown with dates of birth, and has no remove/All action. Selecting a person clears detail, comparison, pagination and person-dependent conditions, while preserving search, activity and view mode. The URL is shareable within the authorized profile. Sidebar navigation resets to Self; an explicit People link or collection filter selects another person. The non-Self header links back to that person. Self uses a neutral pill; another person uses the selection accent. A direct saved-record link resolves its actual owner before showing the collection and detail together. People, Import, original Files and retained Records remain profile-wide.

The non-Self indication uses periwinkle in both themes, text and an icon, without relying on color alone. It fills the desktop header space before Assistant and moves to a full row below the toolbar on mobile. It is not a picker. `person-scope.test.ts` covers a fresh encrypted fictional profile, switching, note ownership, direct links, scope reset, responsive placement and light/dark screenshots; screenshots are optional through `CRS_PERSON_SCOPE_VISUAL_DIR` and must remain outside Git. Mounted tests additionally exercise late ownership responses and content gating.
