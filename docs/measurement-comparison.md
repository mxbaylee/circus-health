# Measurement comparison foundation

The application implements deterministic derived values and individual reviewed semantics through authenticated endpoints. Test-history charts accept an explicit display unit, retain original values, and expose conversion status and rounding. Individual result settings, reviewed comparisons and chart paths are implemented and covered by controlled component/API/encrypted browser checks; real-provider/device release gates remain in [the work list](application-todo.md). Reference ranges remain in their original units; converted range bands and normalized optical trends are excluded. Numerical similarity alone never suppresses relationship review.

## Source and derived representations

`shared/measurement.ts` keeps the accepted source's literal value, unit, comparator and date alongside its exact assertion reference. The parsed decimal retains written fractional digits, exponent, negative zero and lexical reporting quantum. Accepted originals and clinical rows are unchanged. Binary floating point never participates in parsing, conversion, rounding decisions or numerical equality: exact fractions serialize as decimal-string `numerator` and `denominator`. Derived comparison values are rebuilt from retained assertions, accepted semantic decisions and versioned code rules, not made a new durable source of truth.

When an exact printed result literal ends with the same separately retained structured unit, `shared/measurement-value.ts` can suppress a second display copy at an exact lexical boundary, including for a retained range or text result. Numeric parsing is stricter: it separates the suffix only when the remainder is a supported number/comparator. The exact structured unit corroborates either spaced or attached notation without aliases or case folding. The literal and structured unit remain byte-for-byte unchanged. A missing or differently spelled unit, exponent-like unit suffix, trailing prose, invalid grouping or other coercion stays unparsed, and presentation keeps mismatched fields visible rather than hiding the discrepancy.

`deriveMeasurement(input,targetUnit,decimalPlaces?)` returns an explicit status and, only when supported, a conversion containing canonical source/target units, alias usage, exact factor and value, terminating decimal when available, comparator, explicit point/bound/approximation role, converted lexical quantum and optional reviewed rounding increment. Display uses nearest ties to even, a bounded chosen decimal-place count and a signed exact rounding error. A repeating decimal keeps its exact fraction. The source text remains available regardless of conversion or display failure.

The parser accepts bounded signed decimal and scientific notation, optionally prefixed by `=`, `<`, `<=`, `>`, `>=`, `≤`, `≥`, `~` or `≈`. A separate comparator must agree with an embedded qualifier. An exact inline unit may be separated only through the rule above; commas, ranges, textual interpretations, plus/minus uncertainty and numeric coercions are not interpreted for conversion. Processing limits are 256 characters, 120 coefficient digits, exponent magnitude 100 and display precision 0–30 decimal places. Unsupported values retain their literal source text.

## Verified unit subset

Rule version `circus-measurement-v1-ucum-2.2` uses a fixed case-sensitive registry, not a full UCUM expression parser. UCUM defines metric prefixes, liter as a cubic decimeter, `L` and `l` as equivalent symbols, and avoirdupois mass codes. It permits limited implementations with fixed expressions/factors. [UCUM 2.2 specification, §§2–4, 27, 31 and 39](https://ucum.org/ucum).

The metric factors use exact powers of ten: kilo 1000, deci 0.1, centi 0.01, milli 0.001, micro 0.000001 and nano 0.000000001. [NIST SP 811, chapter 4, SI prefixes](https://www.nist.gov/pml/special-publication-811/nist-guide-si-chapter-4-two-classes-si-units-and-si-prefixes).

The registry includes:

- Mass: `kg`, `g`, `mg`, `ug`, `ng`, `[lb_av]`, `[oz_av]`.
- Length: `m`, `cm`, `mm`; volume: `L`, `dL`, `mL`, `uL`.
- Mass concentration: `g`, `mg`, `ug` and `ng` divided by each of `L`, `dL` and `mL`.
- Amount concentration: `mol/L`, `mmol/L`, `umol/L`, `nmol/L`.

Avoirdupois pound and ounce factors are exactly 453.59237 g and 28.349523125 g. The reverse conversion remains a rational rather than a rounded reciprocal. [NIST Handbook 44 (2026), Appendix C, mass tables and exact pound definition](https://www.nist.gov/document/2026-nist-handbook-44-appendix-c).

Application aliases are an explicit allowlist: gram/kilogram/milligram/microgram names and plurals, Greek micro symbols in supported micro units, and lowercase liter spellings. They preserve original notation and expose alias usage. Case is not globally folded; arbitrary whitespace or UCUM annotations are not discarded. Plain pounds/ounces are ambiguous because customary mass systems differ; use explicit codes only. Percent, `U`/`IU`, molarity abbreviations, unknown units, arbitrary activity units and optical units remain unavailable. There is no mass-to-amount conversion based on an assumed molecular weight and no conversion across quantity families.

## Semantic review and numerical agreement

A supported dimension alone is insufficient. A current accepted semantic binding supplies explicit quantity, dimension, region, specimen, method and meaning identifiers for one exact source assertion. Unknown or omitted semantic fields block automatic comparison. Use `not_applicable` only when explicitly reviewed as such; an unknown method must not be replaced with it for convenience. Identifiers are opaque reviewed meanings, not label matching rules. Host bindings also pin the selected profile and accepted subject. Equal dates, labels, codes or values never create a binding or establish one clinical event.

`compareMeasurements(left,right,targetUnit,decimalPlaces?)` returns the two separate projections and one numerical outcome: exact, consistent with rounding, different, bounded, approximate or unavailable. It compares compatible semantic tuples and the same reviewed profile/subject. Bounds remain converted thresholds (use their exact fraction/decimal, not a rounded display value, and never plot them as observed point values); approximate literals have no invented uncertainty interval. Equal rounded display strings do not determine equality.

Written digits expose a lexical reporting step; they do not prove measurement precision. Rounding agreement requires a separately accepted precision statement `{increment,basis,evidence}` with basis `source_statement` or `explicit_review`. Increment is positive, expressed in the source unit, and must contain the reported value on its grid. The comparison uses strict overlap of nearest-rounding intervals after exact conversion, excluding contact only at an unspecified tie. A side without a known increment contributes only its reported point. This describes numerical consistency under the stated rounding model, not biological variation, instrument uncertainty or clinical equivalence. There is no global percentage tolerance.

Every comparison returns `clinicalEquivalence: not_determined`, `mergeAuthorized: false` and `warningSuppressionAuthorized: false`. A future relationship-aware caller must separately establish the current reviewed relationship before suppressing warnings or choosing a display preference. Distinct source occurrences remain distinct even when their values are exactly equal on the same date.

## Host integration contract

`server/measurement-semantics.ts` currently supports accepted Self scalar observations and procedures with retained original evidence. It rejects unsupported documents/optical mappings, medication dose semantics, unknown subject and unaccepted input. This bounded adapter does not invent mappings for legacy rows or replace missing unit interpretations.

- `previewMeasurementSemantics(db,root,profileId,request)` accepts `MeasurementSemanticRequest` from `shared/measurement-semantics.ts`: `{kind,recordId,semantics,precision,reason}`. Both `semantics` and `precision` are required, with explicit null for absent precision; null semantics and precision explicitly revoke the individual mapping. It verifies source bytes and returns the exact reference, literal source, subject, original evidence links, rules version, previous decision, revision and preview token. No mutation occurs.
- `applyMeasurementSemantics(db,root,profileId,input)` accepts the unchanged preview request plus its `reference`, `rulesVersion`, `version`, `previewToken` and stable `operationId`. It revalidates the current exact scope for new operations, appends a decision to the existing accepted `manual_batches` journal inside the established durable transaction, and publishes through existing curation. Lost-response retries return the retained decision; changed operation content conflicts. Optional `durability.pending` reports portable publication retry state.
- `acceptedMeasurements(db,root,profileId,records)` is a bounded synchronous batch read for up to 256 explicit `{kind,recordId}` references. It preserves requested order and occurrences, returns `measurements`, `count`, `complete: true`, revision and unique verified-original count, and rejects oversize batches rather than truncating. One local verification set checks a shared retained original once within that call; the set never escapes or survives another read. Changed archive revision fails the batch. Use this for explicitly requested converted chart data.
- `acceptedMeasurement(db,root,profileId,kind,recordId)` returns trusted `MeasurementInput` plus `semanticStatus` (`none`, `current`, `stale`, `revoked`) and the last retained decision. Only current decisions produce a binding. It rechecks retained originals and does not mutate a clinical record. Pass this host-resolved input to the shared pure functions; never accept a client/model-supplied binding as authority.

Exact references reuse the existing accepted pair contract: profile/kind/record, source-record identity/version, full accepted-row state hash and linked-original evidence hash. A correction, changed evidence, source occurrence change or new rule version invalidates the binding. Semantic history lives separately in the existing journal so saving it does not invalidate its own row-state pin. Replacement/revocation appends a decision with `previousDecisionId`; an old replay cannot revive an earlier mapping. Both portable rebuild and actual encrypted cache-loss recovery retain the accepted semantic/precision decisions while regenerating comparisons deterministically.

The shared clinical-review route handler mounts GET measurement and POST measurement-preview/measurement-apply inside the existing authenticated profile/session/origin dispatch, with bounded JSON requests, host-resolved originals and stable operation IDs. See the maintained [API contract](../src/server/API.md#reviewed-measurement-semantics). The trends endpoint and chart adapter select units explicitly and expose original values and conversion/rounding labels.

## Reusable display and settings components

`MeasurementSettingsAction` in `app/features/clinical-review/MeasurementSettingsAction.tsx` is a callback-based entry action. Pass `target: {title,measurement: AcceptedMeasurement,referenceText?,evidence?}`, `preview(request)`, `apply(exactReviewedPayload)` and `onApplied(result)`. Detail views can mount it in an individual observation's EntryActions beside correction and relationship controls. The agreed profile-authorized host routes are GET `/clinical-review/measurement?kind=observation&recordId=…`, POST `/clinical-review/measurement-preview` and POST `/clinical-review/measurement-apply`; the central dispatcher enforces profile and session authorization.

The dialog begins from a current accepted binding only. It never fills missing semantic fields from a label or unit. The user supplies complete reviewed meaning and a reason, with a separate optional precision statement; unknown precision remains null. Withdrawal is an explicit previewed operation. A successful preview shows exact source evidence, reviewed terms, reason and rounding statement before Apply becomes available. Editing invalidates that preview. A known stale rejection requires a new preview. An uncertain reply or pending publication retains the exact operation ID and payload for Retry Apply, including when the dialog is closed and reopened. Target changes invalidate old previews and ignore late callbacks. `onApplied` is delivered once publication succeeds; pending publication stays visibly saved with a retry action. Focus returns to the entry action after closing.

`MeasurementComparison({left,right?,initialUnit?,decimalPlaces?})` accepts `MeasurementDisplayTarget` objects containing trusted measurement inputs plus title, optional literal reference text and original evidence links. `MeasurementValue` can render one result, and `MeasurementOriginal` exposes the unchanged source section. Unit selection is a local display choice, not a new semantic decision or source correction. Both source occurrences remain rendered, including on the same date or after exact numerical agreement. Bounds use the exact converted threshold, never a rounded threshold displayed as a point. Contradictory written/stored qualifiers remain visible and prevent conversion.

Reference-range strings are preserved verbatim with an explicit original/unconverted label. These components do not infer a structured range, change an age/specimen qualifier, calculate normality, suppress a source assertion, or decide chart membership. Chart adapters keep that original range accessible and omit converted range bands; adding those bands requires a separately reviewed bounded range conversion contract. Ambiguous or missing ranges must not be silently interpreted. Optical measurements remain excluded.

## Converted chart adapter

For an explicitly selected supported display unit, the chart requests `/trends?unit=…` with at most 256 selected results and attach optional `Observation.measurement: DerivedMeasurement` without changing the original point fields. `app/data/measurementChart.ts` exports `transformTrendMeasurements(trends)` for use immediately before `comparisonChart`. It returns plotting copies, preserving every occurrence, and rejects an oversized conversion view rather than silently truncating. Keep ordinary, unrequested chart loads on their existing path.

Only current converted point roles that match the original record/source/value/unit/comparator receive a derived drawing value. Exact fractions become `Number` solely for pixel placement; overflow, underflow or nonfinite values remain unplottable. That approximation must never enter numerical equality, relationship decisions or source persistence. Same-date coincident or nearly equal values keep every source identity. Existing missing/partial date and entered-in-error exclusions still apply.

Converted bounds and approximate roles become plotting gaps even if the source contains a numeric value. Unsupported, stale or mismatched conversions keep the original value and original unit, with a nonconversion reason. Converted plotting copies clear `reference` so an original-unit reference range cannot become a band on a converted axis. No reference string is parsed or normalized.

Use `measurementChartDetails(point)` for result/tooltip annotations. It returns conversion status/reason, exact converted fraction, converted display and rounding label, original literal display, and the original value/unit/comparator/reference fields with `Reference range (original, not converted)`. Recorded-values disclosure renders those notes alongside original values and preserves navigation to the original observation. Reapplying the adapter to its own plotting view restores from that metadata before conversion, avoiding double conversion. The adapter never hides a source assertion or chooses a clinical winner.

The chart unit is stored in the `compareUnit` URL parameter. Selecting a different primary measurement resets it with the extra comparison series; search and date filters survive. The unit control remains available after conversion errors so Original units can restore the full history. Reviewed mutations reload the chart without silently replaying a write.
