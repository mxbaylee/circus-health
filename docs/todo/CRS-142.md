Status: open. Remainder of CRS-122, deleted during backlog grooming on 2026-09-30. Parts of CRS-122 landed without a scoped replacement ticket, so this file collects what is left. Line numbers were checked at `1e6fa50`; re-verify before editing.

## User Story

As an [Operator](../design/personas.md#operate-and-recover),
I want an update to keep filing records for the right person and opening my saved review links,
So that ordinary household filing stays reliable after the installation changes.

## Plain-English User Walkthrough

1. Update the installation and return to a report you were reviewing.
2. Open its saved review link and continue filing records for the intended person. Ambiguous ownership still asks for review.
3. If the installation cannot read a source or use an old setting, see a specific explanation and what needs attention before continuing.

## Acceptance Criteria

### Scenario: A refusal test proves the named refusal

Given the eight matcher-free identity assertions listed below,
When each is tightened to its intended error code and message where needed,
Then a different failure cannot satisfy it,
And route-level cross-profile, missing/unknown-group, stale and malformed requests are refused without writing confirmation.

### Scenario: Contributor configuration and OCR evidence are explicit

Given a retired HEALTH_* or CIRCUS_* setting with a runner-read CRS_ counterpart, or missing Tesseract,
When contributor checks run,
Then retired settings fail with their replacement and missing OCR is an explicit outcome,
And the owner's CI-versus-image decision determines the qualification lane; image installation alone is not a passing OCR run.

### Scenario: Review navigation and concurrent PDF failures are qualified

Given an encrypted profile and current browser fixtures,
When Import deep links, the historical Sources redirect and the named journeys are exercised, and the PDF concurrency case runs under full-suite load,
Then navigation reaches the same intended review and results are recorded on the current tree,
And fixes preserve ownership/destination/recovery, page-limit, descriptor-privacy and cleanup assertions; an isolated pass or an old receipt closes none of that scope.

## Decision and why

A test that passes without checking the failure it is named for is worse than no test, because it reads as coverage.

- **Caregiver:** the identity refusals in R42 are what keep a parent's result out of a child's record. An assertion that accepts any thrown error would still pass if the refusal became an unrelated crash.
- **High-precision tracker:** real OCR and opt-in real-process tests are how a large backlog is qualified. Skipping them silently because of a stale variable name makes a failed qualification look like a pass.
- **Receiving clinician:** a flaky page-limit classification could label a readable PDF unsupported, and then the packet looks complete when it is not.
