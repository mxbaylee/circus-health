# 🧮 CRS-157: Establish legacy model-pass baselines without redundant replay

Status: open. Remainder of CRS-118's restart work. Current-format completed model passes persist sourceExtraction.stepsAtModelPass; legacy review_ready items receive a baseline on hydration. Older queued/running journals can contain cumulative capture steps and proposals without a baseline. Those counts alone cannot distinguish already covered work from new unread capture, so the importer can request an additional billed pass after upgrade. A completed pass then persists the baseline.

## Requirements

1. Inventory retained legacy journal, proposal-dependency and provider-receipt formats to identify durable proof of the capture work covered by a completed model pass. Do not infer coverage from a proposal's existence, a cumulative count, wall-clock timestamps or disposable SQLite alone.
2. Hydrate a baseline only when that proof establishes it. Preserve genuinely new capture and conservative handling of unknown provider outcomes. Keep explicit Stop authoritative and explicit Resume able to request work.
3. If coverage cannot be established safely, keep the replay limit visible and account for the additional model request with bounded, content-free diagnostics. Do not silently skip unread evidence or turn an unknown attempt into a successful result.
4. Use independently fictional legacy fixtures to count model requests across hydration and repeated recovery: zero redundant passes when covered work is proven, continued interpretation of new evidence, and retained handling of ambiguous active journals. Persist only changed scheduling fields.
5. Update maintained recovery and processing documentation with the supported migration and remaining limits. Run current format, typecheck, focused batch/assistant/recovery tests and an independent passing grade before deleting this ticket.

## Open question

Which older durable receipts establish a pass's exact covered capture boundary? Inventory current code and retained formats before selecting the migration rule; a count-only baseline would be unsafe.
