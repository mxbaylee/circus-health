# CRS-231: Keep Large Package Inventories and Unfinished Work Manageable

Status: implementation and qualification in progress. This ticket has not merged.
The implemented [paged authority](../data/intake-state-storage.md#v4-collections-and-selected-publication)
and [bounded consumers](../data/intake-bounded-views.md) do not by themselves close
the remaining requirements below. CRS-232 and CRS-233 retain their separate scopes;
unfinished requirements here must not be moved there solely to retire this ticket.

## User Story

As a [High-precision tracker](../design/personas.md#build-a-history),
I want to file a complete collection even when it contains many separate files,
So that I can see and finish all of my history without splitting it by hand.

## Plain-English User Walkthrough

1. I add my collection and browse its files a page at a time.
2. I can pause, reopen the app and continue from the same unfinished files.
3. If a file cannot be read, I see its name and what remains to do, and can still download the original collection.

## Acceptance Criteria

### Scenario: Inventory and Process a Collection Without a File-Count Product Limit

Given a retained ZIP fits available storage,
When its inventory and members are read,
Then replace the 10,000-entry, 5,000-file and 2 MiB filename-total memory safeguards with bounded disk-backed traversal,
And inventory, plan units, role proposals, reference resolution, identity/report scopes, model responses and client views read bounded pages without loading every member or pending unit,
And each occurrence retains its original name, ordinal, locator and source binding.

### Scenario: Recover Exact Unfinished Work

Given some occurrences have reviewed roles, dispositions or accepted evidence,
When processing stops or disposable indexes are lost,
Then originals and selected durable authority reconstruct the same inventory and decisions,
And retry neither duplicates accepted work nor treats uninspected scope as complete,
And every failed scope remains located and downloadable rather than becoming a fictional unreadable page.

### Scenario: Preserve Package Safety and Count Work

Given corrupt, unsupported, nested or unusually large fictional packages,
When inventory, selected extraction, replay and recovery run,
Then preserve CRC, exact size, local/central header, path/type, profile, cancellation and source-integrity checks,
And failed partial indexes cannot select successful complete plans,
And peak payload and metadata buffers per step stay independent of archive size and member count,
And staged, written, reread, hashed and durable metadata bytes scale with the processed or changed scope, measured separately from cache rebuilds.

## Remaining Implementation and Qualification

- Finish bounded compact presentation of oversized original names and locators,
  including existing-native upgrades and assistant serialization, without losing
  exact original syntax, duplicate fields or source-bound fragment access.
- Qualify large legacy-record changes through the actual encrypted adapter.
  Preserve accepted field history, refuse modified disposable source columns,
  and verify consumed immutable backing before publication. Bound cold replay
  and the encrypted pre-publication workspace/source checks as well as the
  selected metadata update; a bounded header alone is insufficient.
  Contributor and portable adapters must also reject mutually forged source
  and accepted-version SQLite preimages while immutable accepted storage is
  unchanged. Qualify original-proof reuse across exact own publications;
  replaying the full accepted history for every small change is not sufficient.
- Make complete consumed-artifact and journal-marker physical checks cooperate
  with other host requests. Preserve signed baselines, complete membership,
  current physical checks and interruption/refusal behavior. A logical SQL proof
  alone does not authorize skipping filesystem checks. Include cached summary
  responses and nested source-scope callbacks, not only initial preparation.
  Carry the original consumed-artifact proof through the actual final durable
  publication boundary, including callbacks after staging and index updates.
  Installed SQL policy and unlock authorization callbacks are supported
  application boundaries: raw same-byte replacement of a consumed encrypted
  object from either callback must refuse publication or profile activation.
  A managed-write counter alone does not detect that replacement. Close the
  original complete proof after callback-capable work, then finish through an
  owner-controlled publication or activation path without another such callback.
  Separate live request/source checks from the temporary owned index-to-HEAD
  transition without permitting unrelated authority changes.
  The ordinary ownership commit path also needs this closure: a raw same-byte
  original rewrite in its actual pre-durability callback currently succeeds.
  Preserve the original HEAD, ownership receipt and selected record on refusal;
  compact-metadata-specific closure does not qualify ordinary ownership writes.
  Preserve the complete original parent proof across prerequisite snapshot/catalog
  publications and approved child groups. Each prerequisite must use the same
  final physical closure and an exact owned publication continuation; a successful
  maintenance outcome or a newly observed HEAD is not permission to adopt changes.
  Async preparation must retain its original live owner after temporary report
  verification frames finish. Execute business logic once, then replay only its
  authenticated frozen changes at final publication.
  Qualify callback-capable ownership preview/name rendering after physical
  verification as well, rather than relying only on managed-write controls.
- Qualify lookup work for both first accepted use and subsequent small accepted
  changes, including actual changed-source public operations. Logical witness
  correctness and warm lookup tests do not establish the complete scaling claim.
- Resolve the unchanged filtered-feed and full acceptance scenarios without
  weakening their fixtures or guards; passing focused queue regressions does
  not replace integrated acceptance and encrypted cache-loss recovery.
  Finish the unchanged 257-artifact history, including its source-replacement
  HTTP refusal and cancellation checks. Publication preparation has exhausted
  its host hang guard in earlier runs; completing preview alone is not a pass.
  Remove repeated work and preserve the original guard and mutation assertions.
- Reconcile the full requirement-to-code-and-test matrix and supported recovery
  caller boundaries. A source-reading coverage ledger is not correctness approval.
- Complete independent integrated review, resolve findings and update maintained
  storage, import, runtime and release contracts with actual behavior and limits.
- Integrate current main and qualify the frozen candidate in required CI,
  including both unchanged full histories, acceptance/encrypted recovery,
  continuation, browser journeys and the complete intended test partition.

## Preserved Engineering Requirements

SQLite remains disposable, never recovery authority. Keep exact per-occurrence
decisions and operation identities. Pending units need not be eagerly materialized.
Migration, persistence, pagination and source-pinned reconstruction must agree.
Keep metadata safeguards until every affected consumer has a verified bounded
replacement; do not substitute a new product cap.

Preserve unsupported/encrypted ZIP refusal and all-or-nothing safety validation
unless a separately reviewed partial-inventory policy is adopted. Nested input
needs bounded iterative traversal or a located pending exception, not a silently
increased nesting safeguard. Source-verified inventory reuse must work before an
active plan exists, with correct invalidation and cache-loss reconstruction.
Count subprocess inventory work across traversal and per-member publication, not
only parent-process file activity. Qualify direct-versus-packaged PDF parity,
interruption, exact occurrence separation and encrypted recovery.

Retirement requires independent review and exact-candidate qualification; then
delete this file and its index entry in the completing change.
