# 🧱 CRS-168: Store bounded encrypted diagnostic chunks

Status: open. Storage foundation split from CRS-165. Recorder/download integration is CRS-169; full-run instrumentation and qualification remain CRS-170. This ticket alone changes no capture or download behavior.

## Requirements

1. Reuse vault authenticated encryption and the profile key for a diagnostic-only chunk store outside medical-record manifests, recovery authority and plaintext workspaces. Bind ciphertext to profile and exact chunk identity. Respect vault-close authorization. Never overwrite an earlier chunk as part of appending a later one.
2. Append bounded chunks and evict oldest chunks within fixed chunk-count and byte budgets. Cache the bounded index for a writer lifetime; appending must not reread or rewrite prior chunk payloads or the whole index. Validate input sizes, enforce exact identity/name formats and reject ambiguous append identities. Writes and bytes must scale with new chunks. A retry with the same identity and bytes must not duplicate data; changed bytes must fail.
3. Recover a deterministic ordered retained inventory after reopening. Missing, oversized, malformed or unauthentic chunks produce explicit unavailable/read failures rather than invented empty success. Bound decrypted chunk reads and exported iteration, and report truncation/unknown earlier history honestly. Interrupted publication/retention must not become clinical data authority; interrupted writes and orphan cleanup must stay within a documented fixed allowance.
4. Test encryption at rest, profile/identity authentication, append replay/conflict, retention, corruption, close/reopen and unchanged prior ciphertext. Instrument I/O to compare payload reads/writes and bytes at two corpus sizes. Tests use independently fictional metadata only. Keep medical manifest/head unchanged.
5. Expose this through the existing vault boundary, document limits and best-effort diagnostic semantics, and preserve recorder integration and full-size qualification in their named remainder tickets. This storage primitive cannot establish a complete 900-page history or owner-trial readiness.

Complete with independent review, focused tests and PR CI; delete this ticket/index entry and repoint implemented storage documentation.
