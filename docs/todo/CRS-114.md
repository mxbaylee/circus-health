# 🪓 CRS-114: Remove the repository file inventory and dead code

Status: open. Owner-approved cleanup (2026-09-24, `7dc2390`), not a release gate. An agent can do it.

## User Story

As an [Operator](../design/personas.md#operate-and-recover),
I want installation updates to preserve the features and older records I rely on,
So that maintenance cleanup keeps the app dependable.

## Plain-English User Walkthrough

1. Install an update through the supported setup.
2. Open existing records and use ordinary imports and recovery as before.
3. Contributor checks remain available with instructions that match the supported commands.

## Acceptance Criteria

- **Given** the current inventory tool and its exclusive references, **When** cleanup lands, **Then** the checker and its CI/build/format/documentation references are removed, while real contributor commands remain documented and working.
- **Given** an apparent unused file/export, **When** it is considered for deletion, **Then** reachability includes dynamic imports, workers, launchers, opt-in tests, migrations and old-archive decoding; finder output alone cannot establish that it is dead.
- **Given** the final cleanup, **When** the required checks below run, **Then** they pass and every remaining unused-file report has an explanation; the change description states why each deletion was safe.

## Decision and why

The inventory check only proves that every tracked path matches some classification rule. It never re-checks its hand-written descriptions, most paths get a generic label from a folder rule, and one category is never used, so it adds a CI step without catching real problems. It still runs in CI and passes, which is not evidence that it is useful.

## Requirements

1. Remove `scripts/repository-file-inventory.ts` (the only file under top-level `scripts/`) and everything that exists only for it:
   - the `node scripts/repository-file-inventory.ts --check` step in `.github/workflows/code-checks.yml` (near `:44`);
   - `COPY scripts/ ./scripts/` in `Dockerfile` (near `:16`) and the `!scripts/` and `!scripts/**` lines in `.dockerignore` (near `:15-16`);
   - `"scripts/**/*.ts"` in `tsconfig.tools.json` (keep `src/scripts/**/*.ts`);
   - the top-level `scripts` entry in the `format` and `format:check` globs in `package.json` (keep `src/scripts`);
   - the inventory command in `CONTRIBUTING.md`'s full local reproduction checklist; keep the remaining lane commands intact;
   - in `docs/architecture/code-organization.md`, the "Generate a file inventory" section and the "inventory tooling" clause in the Docker build-context paragraph.
2. Then remove dead code, tree-shaking style: start from real entry points (server start, browser routes, deploy launcher, npm scripts, test globs) and delete files and exports that nothing reachable imports. Candidates, each to be re-verified before deleting:
   - `src/app/pages/Overview.tsx` (unrouted) and `src/app/data/sample.ts` (no consumer);
   - `src/server/query.ts` with `src/server/query-worker.ts`, and the part of `src/server/test/backend.test.ts` that exists only for them (test-only);
   - `src/server/test/native-provider-workflow.integration.test.ts` (obsolete; conflicts with the LiteLLM-only configuration). It is in `externalTests` in `src/scripts/test-suite.ts`; remove that entry too.
   - The import prototype named in the original task was already removed in `2c23374`.
3. Use an unused-file and unused-export finder such as knip as evidence, not authority. A file reached only by an opt-in integration test, a dynamic `import()`, a worker path passed to `fork` or `new Worker`, a migration, or a Docker or launcher reference is live. Keep deliberately retained history: migrations, validation evidence and decoders required for supported-current-format accepted evidence and history. This does not add obsolete-schema compatibility: the owner excludes old-schema support before production (2026-10-01; see the backlog priority notes).

## Completion

Done when `npm run typecheck`, `npm run build`, `npm test` and `npm run format:check` pass, CI no longer runs the inventory step, and a final finder run reports no unexplained unused files. Record what was removed, and why each item was dead, in the change description rather than keeping an implementation plan here.
