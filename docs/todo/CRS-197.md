# 📐 CRS-197: Make the fictional scan-table fixture portable across font metrics

Status: open. A focused prerequisite for [CRS-196](CRS-196.md)'s current large-import baseline, discovered while validating the [scripted contributor runner](../import/import-performance.md#scripted-large-import-runner). This is a fixture-generation defect, not evidence of a clinical import failure.

## Reproduction and affected scope

On 2026-10-02, the unchanged `renderLargeImportPage(largeImportPage(createLargeImportOracle(), 150))` threw `Fictional clinical table cell exceeds its visible column bounds` in an isolated Linux arm64 contributor runtime with Node 24.19.0, `@napi-rs/canvas` 1.0.9 and the repository lockfile. The failure happens before upload, OCR or model requests. The image has DejaVu Sans Mono and Liberation Mono; installing a missing font is not the explanation.

`src/scripts/large-import-fixture.ts` computes table columns at exactly `fontSize * 0.6`, but raster text uses the platform's `monospace` metrics. At 20 px, the page-150 header “Analyte from p149” measures 204.70 px against a 204 px column with DejaVu Sans Mono; Liberation Mono measures 204.03 px. Separator text also fails this check even though the renderer draws it as a line. Merely choosing one of those aliases does not satisfy the strict geometry check.

This prevents contributors from generating the current two-person, mixed native/scan fixture and thus blocks evidence for the patient's large-document import journey. The runner's bounded protocol test deliberately scans page 2 and keeps pages 149/150 native; that does not qualify the full fixture or its scanned split table.

## Acceptance

1. Correct the raster font/layout contract deterministically: measure and fit visible cells or use a reproducible font and layout, while retaining every literal character, readable sizing, separators, page boundaries and original native/scan assignment. Keep the existing 900 pages, six reports, two people, 901-assertion oracle and page-149/150 split row unchanged. Do not remove bounds checks or trim, omit, hide or change clinical content to pass.
2. Test page 150 with the actual supported Linux rendering dependencies and a distinct available font metric environment. Verify visible bounds and inspect the rendered split table; verify the existing OCR/literal checks against the unchanged oracle. Retain independently fictional images and raw validation artifacts outside Git.
3. Generate the full unchanged fixture successfully and verify its page count, native/scan mix, oracle and original hash. Then run the scripted contributor command as a new explicitly identified attempt, preserving the prior failure and all default application limits. A later pipeline refusal is a distinct finding, not permission to weaken the fixture.
4. Update the maintained measured procedure and CRS-196 with the new evidence, run focused tests/static checks and PR CI, and obtain independent review before retiring this ticket. This fix does not itself establish production import correctness, diagnostic completeness or a release-browser qualification.
