# 🧩 CRS-219: Store a disposable transactional source-text rope

Status: open. Storage prerequisite split from CRS-207; depends on [CRS-225](CRS-225.md) and uses the implemented [explicit text-piece engine](../data/text-piece-edits.md), unblocks CRS-220. Reuse the implemented lookup projection lifecycle patterns instead of a parallel accepted-authority store.

## User Story

As a [Records assembler](../design/personas.md#file-and-review),
I want to find and recover the information in my documents as my collection changes,
So that I can assemble a reliable history without losing or distorting evidence.

## Plain-English User Walkthrough

1. I update my collection and search for information from its documents.
2. After recovery I find the same evidence; if something cannot be recovered, I receive a clear explanation.

## Acceptance Criteria

### Scenario: Publish text changes transactionally

Given a selected source has verified exact text and retained piece evidence,
When its text is updated through the caller transaction,
Then the bounded row changes and selected text commit together and reconstruct the exact expected bytes.

### Scenario: Distinguish disposable loss from authority loss

Given a text cache is lost or selected durable evidence is missing or corrupt,
When the source is reopened or rebuilt,
Then disposable loss repairs only from verified evidence and missing or corrupt authority fails without guessing.

### Engineer context

The text projection is disposable: damaged cache may rebuild, but missing authoritative evidence must be reported rather than guessed.

## Detailed engineering requirements

1. Persist CRS-225’s automatically reconciled bounded content and occurrence/link edits in an explicitly disposable namespace excluded from accepted-record capture and portable authority export. Bind the small selected head to the current profile, source identity/hash and exact source serialization. No growing full-text/occurrence row, copied workflow receipt or whole-envelope journal is allowed.
2. Derive edits from retained anchors and the exact next authoritative text through CRS-225; supplied semantic edits alone are insufficient. Reconcile only dirty sources in the caller's transaction using connection-scoped tracking; cold initialization may read each authoritative view once. Warm unchanged sources require no operational intake hydration. Keep countable reads/writes and bounded reconstruction APIs; no persistent derived-table trigger may break copy or rebuild.
3. Updates are atomic through the existing transaction boundary. Qualify rollback, a partly executed projection batch, actual close/reopen, dropped cache tables, total cache loss and real private copy. Clear private readiness on lock/close/failed outcomes. Missing/corrupt derived state can rebuild; missing/corrupt/unsupported durable authority must fail rather than fabricate empty workflow state.
4. Detect malformed schema, cycles/dangling or cross-source piece links, stale heads and source/profile/hash mismatch. Repair only disposable data from selected authority. Reordered/duplicate content and source rename/delete must not erase another source's references or leave stale results. Cleanup must scale with affected references, not repeated global scans hidden from counters.
5. Test initial and changed state with 100/200/300 updates, separately counting logical content/link bytes, SQL allocation, prior-row reads, hashing/serialization and authority cost. No source-search query replacement or production authority activation yet. Run focused transactional/recovery/copy tests, formatting/types, full PR CI and independent review; document the actual cache boundary before retirement.

Reassess scope and split only at useful complexity boundaries. Source originals and accepted versions remain recovery authority; no model calls or heavy imports.
