# 🪞 CRS-257: Make retained duplicate-pair evidence readable, or stop claiming it is

Status: open; PR #71 review finding. Native pair decisions retain an immutable
snapshot reference for the reviewed saved side, but no shipped history, review or
export path reads it. Maintained documentation describes it as readable history.

## User Story

As a [Records assembler](../design/personas.md#correct-a-record),
I want to see the saved evidence that was in front of me when I decided two
records were or were not duplicates,
So that I can later explain or revisit that decision without guessing what I saw.

## Plain-English User Walkthrough

1. I review a new result against a saved record and decide they are the same.
2. Later the saved record gains more evidence from another report.
3. When I open that earlier decision, I can see the evidence I reviewed at the
   time, clearly separate from what the saved record holds today.
4. If the app cannot show that earlier evidence, it says so rather than showing
   today's evidence as if it were what I reviewed.

## Acceptance Criteria

### Scenario: An earlier pair decision shows its reviewed baseline

Given a fictional native pair decision whose saved side later gained evidence,
When the decision is opened from record history,
Then the shown saved-side evidence is read from the retained
`health-duplicate-evidence-snapshot-v1` reference and matches its count and digest,
And current saved evidence is labelled separately and never substituted.

### Scenario: The snapshot cannot be read

Given a reference whose source hash or digest no longer verifies,
When the decision is opened or exported,
Then the app refuses that evidence explicitly and keeps the outcome and reason,
And it does not fall back to current evidence or report an empty baseline.

### Scenario: Reading stays bounded

Given a large retained snapshot,
When it is paged,
Then work counts scale with the requested page, not the full snapshot,
And reading writes nothing durable.

  reviewed native scopes, `evidenceBasis: 'reviewed-pre-projection-v1'`.
- The only reader, `prepareRetainedDuplicateEvidenceSnapshot`
  (`src/server/duplicate-evidence-snapshots.ts:311`), is called only from tests
  (`duplicate-evidence-snapshots.test.ts`, `duplicate-evidence-native.test.ts`,
  `intake-state-bootstrap.test.ts`).
- The app's `SavedDuplicateEvidence` reader
  (`src/app/features/clinical-review/SavedDuplicateEvidence.tsx`) pages
  `health-saved-evidence-v1`, the current saved evidence
  (`duplicate-evidence-index.ts:380-402`), not the retained snapshot.
- Record history lists legacy pairs with outcome and reason only
  (`clinical-relationships.ts:575-596`); `ownership-decision-index.ts:14`
  extracts the reference but nothing renders it. Note exports do not include
  duplicate decisions.
- Docs describing a reader or export: `docs/data/intake-state-storage.md:301`
  ("Historical export cold-sorts only scalar IDs ..."),
  `docs/setup/release-updates.md:472` ("Use a build that understands the
  reference to read or reconstruct this history"),
  `docs/import/import-reconciliation.md:63`.

integrity and future use but is not currently displayed? Either outcome closes
this ticket; the docs must match whichever ships. The scenarios above apply if
the reader ships; a docs-only outcome instead removes every reader/export claim
and states that history shows outcome and reason only.
