# 🗳️ CRS-256: Keep reviewed ownership choices across a report-mode preview refresh

Status: open; review finding from PR #71. In report-mode ownership previews, each
per-record choice is posted to the report-evidence endpoint and then cleared from
the page. Any later full preview (Refresh, **Update preview**, or a Reason edit)
posts no earlier choices, so the server rebuilds the preview without them. This
loses review work; it does not commit a wrong choice, because commit binds to the
server's preview request and unreviewed matches stay blocked.

## User Story

As a [Caregiver](../design/personas.md#correct-a-record),
I want my per-record ownership choices to stay in place while I finish a
correction,
So that I do not have to redo a long review of a misfiled report after a refresh.

## Plain-English User Walkthrough

1. I start moving a misfiled report to the right family member and review its
   records one by one: link this one, keep both for that one, split another.
2. I refresh the evidence, edit the reason, or press **Update preview**.
3. Every choice I already made is still shown and still counted, and only records
   I have not reviewed remain blocked.
4. If a choice can no longer apply because the evidence changed, the page names
   that record and asks me to review it again.

## Acceptance Criteria

### Scenario: Earlier report-mode choices survive a full preview

Given a fictional report-mode preview with link, keep-both and split decisions and
a relationship choice already posted one at a time,
When the person refreshes blocker evidence, edits Reason and updates, or presses
**Update preview** with the same selection and destination,
Then the new preview shows each earlier choice as reviewed,
And the commit request carries those choices exactly once.

### Scenario: A changed basis revokes only affected choices

Given the same reviewed choices,
When the selection or destination changes, or a record's evidence changes,
Then only choices that no longer bind to the shown evidence are dropped, with a
visible "review again" notice naming those records,
And no choice is applied to a record the person did not review.

### Scenario: Retaining choices stays bounded

Given a report with many records,
When the preview is rebuilt,
Then retained choices are sent or referenced without re-posting each one, and the
request and server work grow with the number of choices, not the report size.

## Evidence and Implementation Scope

At PR head `2706c5d`, `src/app/features/clinical-review/RecordOwnershipAction.tsx`:

- `:178-191`: when a single pending choice exists and selection, destination and
  reason are unchanged, it posts to `preview.reportEvidence.url`; otherwise to
  `${prefix}/preview` with the current `decisions`, `nameDecisions` and
  `relationshipDecisions` (`:194-202`).
- `:208-212`: after any report-mode response it clears `decisions`,
  `relationships` and `reportRelationship`, so the next full preview sends
  `decisions: []`.
- Full-preview triggers: `OwnershipBlockerEvidence` `onRefresh` (`:510`, `:759`),
  **Update preview** (`:704-710`), and a Reason edit (`:698-701`) that makes the
  next update a full preview.
- Server side, `src/server/record-ownership.ts:739-745` sets `reviewedDecision`
  only from `owned.decision`, which a fresh preview request does not have.

Name decisions (`names`) are not cleared at `:208-212`; confirm whether they are
affected in report mode before including them. Add component tests with fictional
people covering each trigger, plus a server test that a rebuilt preview reports the
retained decisions.
