# ♻️ CRS-155: Finish live OAuth refresh qualification after natural expiry

Status: open. Remainder of CRS-063. On 2026-09-30, the adopted ChatGPT `health-primary` route's saved access token was still unexpired; the guarded probe returned `pending_natural_expiry`. A fictional request and earlier sign-in/recreation checks show current access, but they cannot establish refresh after expiry. Do not alter the expiry field, rotate or copy real tokens, or treat fictional offline responses as this check.

## What exists

The supported root `npm run qualify:oauth` command uses the external state and selected LiteLLM config. It requires `CRS_OAUTH_QUALIFICATION=1`, checks that the selected route is exact `chatgpt/...`, and emits a mode-600 metadata receipt outside Git. An unexpired token yields `pending_natural_expiry` without an auth write or network request. After natural expiry, a disposable pinned container forbids device login while calling the real refresh path, checks a changed persisted token and future expiry, then a second clean container checks reuse without a refresh or sign-in. It neither interrupts an already running app/proxy stack nor sends a model request. The maintained [model-provider guide](../setup/model-providers.md#provider-routes) gives the command and evidence limits; the network-disabled pinned compatibility tests use only fictional tokens.

## Remaining acceptance

1. When the adopted token naturally reaches the pinned authenticator's expiry guard, run the command against the actual external state and retain its `passed` metadata receipt. A pending or failed receipt does not close this check. Do not log, attach or commit tokens, device codes, credential paths or provider error bodies.
2. After the observed refresh, create a fresh supported Compose proxy/application container with the same state and selected alias, and run a tiny independently fictional tool challenge. Confirm the route works without interactive sign-in, is still the intended model, and persists through another clean recreation. Keep this evidence separate from the authenticator receipt and from clinical import qualification.
3. Repeat for every OAuth route actually adopted for the installation. If a route does not use OAuth (for example a local Ollama model or an API-key route), record why it is outside this check. If the adopted route changes, do not claim an earlier route's receipt for the new one.
4. Update maintained setup documentation with the result and limitations, obtain an independent passing grade, and delete this ticket and index entry only when the live acceptance above passes.

No further owner decision is needed. The owner has authorized small billed fictional provider requests. If fresh sign-in becomes necessary, the owner must complete the provider's device prompt in their own terminal; the qualification runner itself deliberately refuses login.
