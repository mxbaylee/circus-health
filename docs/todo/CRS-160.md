# 🪡 CRS-160: Durably assign historical raw assertion ownership

Status: open. Backend remainder of CRS-156; the [evidence inventory](../../src/server/NOTE-EXPORTS.md#historical-raw-assertion-ownership) and packet guards are implemented. Unblocks CRS-161. High effort: split into further focused implementation tickets before starting, or obtain owner grading before merge.

## Existing boundary and reason

Provider packets currently include raw allergy, condition, visit and immunization assertions only with unique report_subject evidence. The ownership-correction flow in record-ownership.ts operates on normalized clinical record IDs, which these raw assertions lack. Missing ownership does not mean Self. The receiving clinician and caregiver need correct attribution without losing original evidence.

## Requirements

1. Use the maintained [historical-ownership evidence inventory](../../src/server/NOTE-EXPORTS.md#historical-raw-assertion-ownership). Identify exact historical assertions provable from retained accepted mappings or exact report-scoped decisions, using independently fictional migrated fixtures. Validate profile, exact source occurrence/member, original hash, candidate/version and later corrections/revocations. Never derive ownership from raw names, shared source file, clinician/relative mentions, or a missing person field. Conflicting decisions and mixed-family scope remain unresolved. Unsupported historical formats require review, not guessed decoding.
2. Provide profile/session-authorized preview and commit operations for explicit assignment of one unresolved assertion to an existing Self or managed Person. Preview supplies retained original/locator and proposed person; commit pins evidence and person versions, verifies original integrity, records the profile user's attestation and preserves conflicts for review. An unavailable original or changed authority must fail explicitly. Stable operation IDs make retries idempotent. Include stale preview, concurrent correction, cross-profile/session and locked-state tests.
3. Append changed ownership evidence and a bounded actor/time/reason/proof receipt through existing durable record storage. Preserve originals and all accepted versions; no source/file/profile snapshots in each receipt. Count journal growth at two corpus sizes and verify crash/retry and complete cache-loss reconstruction. Distinguish identity assignment from clinical acceptance or provider amendment.
4. Resolved assertions become available only in their person's packet. Generic omission remains while any eligible ambiguous assertion remains; never reveal omitted titles, counts, contents or possible owners. Test older profiles including Self, managed Person, clinician mention, conflicts and mixed-family exports before/after rebuild. Proven restoration must not override later reviewed corrections.
5. Document actual supported formats, restoration procedure and limits in maintained import, storage, API and packet references. No automatic restoration claim until migrated-fixture evidence supports it. UI and rendered journey remain CRS-161.
