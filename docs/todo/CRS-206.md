# 🗝️ CRS-206: Compact intake lookup projections

Status: open. First prerequisite split from high-effort CRS-205 after reassessment. Builds on the implemented [access boundary](../import/intake-state-access.md); unblocks [CRS-209](CRS-209.md). Production intake still stores its operational view in source details.

## Contract and scope

Replace the access boundary's whole-workflow SQL lookups for report discovery order, acceptance replay and identity confirmations with compact, disposable indexes. Ship these adapters against current production authority; do not activate the new intake authority or change public semantics in this slice. Originals and accepted records remain durable evidence. Projection tables are never recovery authority.

## Acceptance

1. Preserve the existing global maximum integer discovery order over original intake report groups, original-only acceptance-operation lookup and exact retained receipt replay, and global identity-confirmation/name-support behavior including non-original sources currently included. Preserve array order and existing duplicate/tie selection behavior where observable. New-group allocation remains in the caller's publication transaction and sees earlier writes in that transaction; rollback cannot consume or duplicate committed order.
2. Use bounded per-source metadata and individual indexed contributions/references, not growing workflow, receipt or reference arrays in a row. Reconcile only changed projection rows. Keep unchanged receipt payloads untouched when another receipt changes. Lookup must not hydrate every intake on each call. First build or deliberate cache-loss rebuild may inspect current authority once; count that separately from warm calls and changed-source reconciliation.
3. Update or invalidate the index coherently for source insert/update/delete, kind/identity changes and raw SQL paths used by recovery/copy. A small dirty-source set or equivalent may detect changes; a global revision change must not trigger a full workflow rebuild on each transaction. Shared-boundary writes, projection updates and accepted clinical writes retain the existing transaction boundary. Preserve commit/rollback and dirty durable-projection refusal behavior.
4. Use an explicit disposable namespace excluded from accepted-record capture, such as existing __record_* conventions. Validate projection schema/profile binding, rebuild after loss, lock/reopen and selected-authority reconstruction, and refuse to use stale state after an ambiguous durability failure. Do not copy invalid indexes across profiles. Connection-scoped triggers must survive drop/recreation safely; persistent triggers must not break private-copy owner/path rewrites after derived tables are removed.
5. Test multiple sources, large untouched workflows, repeated warm lookups, changed/deleted/reordered contributions, failed transactions, malformed authority, copy/rebuild and real discovery/acceptance/ownership consumers. At 100/200/300 contributions demonstrate changed-row writes and indexed warm access with actual counts, including initial build, reconciliation reads and bytes, SQLite allocation and durable-capture exclusion. Full-view CPU work is disclosed separately. Do not claim this resolves the still-growing source details authority.

Search is [CRS-207](CRS-207.md), private-copy framing is [CRS-208](CRS-208.md), activation is [CRS-209](CRS-209.md), and actual import/review growth qualification is [CRS-210](CRS-210.md). Future activation must bind these indexes to selected intake authority rather than leave source details as a hidden second authority.

Validation uses fictional data, focused local tests, formatting/type checking, full PR CI and independent grading. Before implementation, reassess effort and split again if the remaining work exceeds medium effort. On completion delete this ticket and its index entry, document implemented behavior and repoint dependents.
