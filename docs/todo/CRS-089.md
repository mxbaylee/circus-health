# 🪶 CRS-089: Make the model gateway lighter and less patched

Status: open. Reframed during backlog grooming on 2026-09-30 from "evaluate Bifrost as a LiteLLM replacement". Bifrost is now one possible solution, not the goal (owner, 2026-09-30). Line numbers were checked at `1e6fa50`; re-verify before editing.

## Decision and why

The goal is the gateway's cost to the household, not a particular product. The problems are:

- LiteLLM's memory footprint on a small laptop;
- the compatibility patch the project carries on it.

Any option that reduces either one qualifies, including keeping LiteLLM and tuning it.

- **Operator:** runs the app on a small laptop, alongside Docker's VM, Chromium for PDF export and the app itself. Memory the gateway holds is unavailable for imports.
- **High-precision tracker:** long imports make many model requests. Added requests, retries or bytes from the gateway multiply across them.

## Where it stands

- The gateway is pinned `litellm/litellm:1.99.1` with one patch, `patch_chatgpt_stream_semantics.py`, applied at build time (`deploy/litellm/Dockerfile`). It has its own tests for native PDF, login, configuration and response diagnostics.
- `compose.yaml` limits LiteLLM's CPU and process count, but not its memory. It starts with default workers (`deploy/litellm/entrypoint.sh`).
- Its memory has not been measured in this project. No baseline exists.
- LiteLLM owns the ChatGPT subscription device sign-in, token storage and refresh ([docker-ai.md](../setup/docker-ai.md)). Any replacement must provide the same, or the app must move to an API-key route.

## Requirements

1. Measure first. Record idle and peak memory, startup, and requests, retries and bytes per model request for the current LiteLLM setup on fictional imports. Record these as counts and bytes, and never as a seconds bound for model work, per `AGENTS.md`.
2. Try the tuned-LiteLLM option and record the same numbers. Keep it if it holds up on the regression suites in `deploy/litellm`.
3. Pursue a replacement only if tuning leaves a problem worth solving. A replacement must pass the same fictional contract cases: unchanged PDF bytes, same-page PNG fallback, text and tool aggregation, forced SSE, empty terminal output, usage fields, cancellation, and no model fallback. It must also meet the sign-in gate above for the route in use.
4. Keep a tested way back to the current LiteLLM setup until a replacement is verified.

## Completion

Record the measurements and the chosen option in [docker-ai.md](../setup/docker-ai.md) or [model providers](../setup/model-providers.md). Run the `deploy/litellm` tests and the proxy-bridge suites. Obtain an independent passing grade before deleting this ticket, per `AGENTS.md`.
