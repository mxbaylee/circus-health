# 🔎 CRS-270: Find visible multiword PDF phrases across text-item spacing

Status: open. Found during CRS-152's fictional deployment qualification. The identity-grounding repair preserves original text and does not change PDF search or retained text offsets.

## User story

As a [Records assembler](../design/personas.md#read-unusual-evidence),
I want searching for a phrase I can see in a PDF to find its original page,
So that I can locate and check the evidence without manually scanning the document.

## Plain-English walkthrough

1. Open an original PDF and search for a visible phrase containing several words.
2. See the matching page and a useful excerpt, even when the PDF stores those words as separate text pieces.
3. Open the original at that page and verify the wording; a different phrase still returns no match.

## Given–When–Then acceptance

- **Given** a fictional PDF whose visible phrase is split into PDF text items, including separate space items, **when** that phrase is searched through both supported PDF navigation paths, **then** the correct original page and excerpt are returned without requiring the user to type artificial repeated spaces.
- **Given** different wording, punctuation, literal regular-expression characters, page boundaries and genuine layout gaps, **when** search compares the requested phrase, **then** it preserves the existing documented search semantics and does not manufacture a match by deleting words or joining unrelated pages or regions.
- **Given** bounded search pages and continuation, **when** matching uses a comparison representation, **then** page identity, excerpt limits, original positions and continuation remain correct, and retained original bytes and stored text/offset contracts remain unchanged.
- **Given** a large original or changed source, **when** either search path runs, **then** existing bounded reads, cancellation and source-identity refusal remain enforced; this fix does not replace the separate work limits or repeated-hash requirements.

## Current evidence and scope

On 2026-10-16, an independent reviewer reproduced the problem with the actual `searchPdfEvidence` and `searchPdfEvidencePage` workers against the independently fictional qualification PDF. The visible phrase `Fictional Qualification Person` returned no matching page and a null addressed-page excerpt. The controls `Fictional` and `QUALIFICATION REPORT` matched. The test used no provider, database mutation or clinical acceptance.

`src/server/intake-pdf-worker.ts` appends a space after every non-EOL PDF.js text item in both `searchPdf` and `searchPdfPage`, including items already containing a space, then uses substring matching. Public callers include `src/server/intake-navigation.ts` and `src/server/intake-evidence-navigation.ts`. Qualify the fix with independently specified visible phrases rather than deriving the query from the same extraction output being tested. Preserve supported case handling and literal punctuation; do not use patient-name canonicalization as a search policy.

This is separate from the identity quote comparison and its birth-date/role safeguards. It contributes to [CRS-115](CRS-115.md)'s broader readable-evidence qualification, but neither ticket must wait for the other to begin. [CRS-247](CRS-247.md) owns cooperative source-search work limits; [CRS-267](readme.md#crs-267) owns repeated original hashing during navigation. Avoid changing retained text serialization merely to repair search comparisons.
