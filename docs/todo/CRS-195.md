# 🧪 CRS-195: Exercise large imports with a scripted processing-to-review runner

Status: open. Medium-effort, large-impact production prerequisite split from CRS-194. The implemented 900-page fixture/oracle and graders lack an executable full processing path: existing small HTTP fixtures submit proposals directly, while the controlled 100-page test qualifies transport/continuation rather than the clinical oracle. Supply reproducible application evidence that can reveal the next production blocker.

## Scope and acceptance

1. Add an explicit opt-in TypeScript contributor runner with a fresh independently fictional encrypted profile and artifacts outside Git. Refuse existing/private profiles and unsafe output locations; never fall back to a real provider. Keep setup self-contained and portable. The runner exercises the contributor runtime through normal HTTP upload, the upload-created automatic batch, extraction, real `ProxyModelBridge`, tool handlers, scheduling, proposal and review APIs. Only upstream inference is scripted through the bridge's fetch boundary. This does not qualify the supported npm → Compose → LiteLLM deployment or release browser workflow.
2. Generate the existing unchanged compact 900-page mixed native/scanned fixture and literal 901-assertion oracle. Obtain the implemented recording check before upload. Retain its dated current attachment evidence and warnings. Recording unavailability, refusal and known diagnostic omissions become explicit blocked/incomplete evidence; never treat the check as complete-run proof or alter upload/context/retention defaults to force a pass.
3. Use an acknowledgement-driven scripted upstream that creates/reads normal extraction plans, requests actual original page derivatives and proposes through `health_intake_batch` only after corresponding physical-request delivery. Validate source/version/unit acknowledgements. Track actual page media hashes at the request boundary; a successful host read alone does not prove delivery. Incorrect or absent delivery must not support a scripted proposal.
4. Independently author scripted envelopes for all three clinical kinds, six reports, both people and the page 149/150 split row. The literal oracle is input to grading only, never upstream instructions or generated proposal answers. Label scripted answers as host-processing evidence, not live extraction/OCR fidelity; unmeasured observations and usage remain unknown.
5. Preserve automatic coordinator behavior. Do not secretly call convert, retry, Resume or budget extension. Distinguish app/provider limits, continuation boundaries, user cancellation and explicit harness count bounds. A harness-bound stop produces retained incomplete evidence, not a model-speed failure. No model-work pass/fail time limit.
6. Gather actual proposal/review and retained report-authority snapshots; run the implemented proposal-stage grader against the whole oracle, preserving missing, exceptional and unresolved ownership scope. Do not automate clinical acceptance in this slice. Retain the unchanged original/hash, terminal/interrupted batch evidence, per-physical-request composition/work counts, grade and server diagnostics outside Git. Durable report writes scale with new evidence; never copy all history or full review snapshots on every poll. Supply a safe aggregate result and a usable review entry for later browser work, with lifecycle/retention instructions.
7. Focused tests exercise a bounded mixed native/scan protocol through actual upload → tool reads → physical delivery → proposal → review, two people and the split row; missing media and stale/wrong acknowledgements; transport/refusal/recording failure and count-bound interruption; and real continuation behavior without hidden Resume/extend. Each retains truthful failure/incomplete evidence, without acceptance or real-provider fallback. Run one explicit 900-page attempt to establish actual runner behavior; keep that workload out of ordinary unit tests.
8. A passing implementation may expose an unsuccessful import. Preserve the failure, file actionable findings with sizes and reproduction/acceptance checks, and do not weaken defaults, fabricate completeness or repair records silently. Update maintained documentation with the implemented procedure, measured safe counts and actual limits; run focused local checks and full PR CI, obtain independent review and retire this ticket. Carry unfinished CRS-194 requirements into a scoped successor.

## Remaining qualification

Browser delivery/loss accounting, historical build/config attribution, full-size retention/recovery, release desktop/narrow review and complaint download, acceptance/cache rebuild, supported Compose qualification and adopted-route trials remain open. The scripted contributor run does not close those production gates; use its evidence to prioritize the next blocker.
