# 🧵 CRS-169: Retain and export diagnostic metadata across recovery

Status: open. Integration remainder of CRS-165; the [encrypted chunk store](../data/record-version-storage.md#diagnostic-chunk-storage-boundary) is implemented. Full-size budgets, additional instrumentation, actual release browser complaint reconstruction and baseline remain CRS-170. Keep this scope focused; split further if implementation reveals high effort, or obtain owner grading before merge.

1. Connect the existing sanitized metadata recorder to the encrypted diagnostic chunk store only under explicit detailed recording opt-in. Use bounded pending buffers and changed-data writes, flush on normal lock/close/export, and label any crash-tail, retention, oversize, read/write or unavailable history as incomplete. Failure must not disrupt clinical work. No raw payload capture or clinical data copies.
2. Preserve current memory-window and summary semantics. Export retained archive events with runtime/window identity so restarts and current-memory duplicates are distinguishable. Re-salt source/run identifiers with the export's existing salt, preserve approved random correlation references, validate recovered schemas/fields, and never expose arbitrary stored strings. Old/missing/corrupt data remains explicitly unavailable or partial, never invented coverage.
3. Attach only after authorized unlock, clear plaintext pending/index state and references on detach, and guard every read/write through the open vault. Verify encrypted HTTP session isolation, lock/unlock, fresh process/container equivalent, and SQLite/cache-loss recovery. Prior stored diagnostic metadata may remain downloadable when future capture is disabled; explain that distinction.
4. Update the normal desktop/mobile download's coverage explanation and JSON. Exercise a mounted download of actual retained data; ensure clear status/read failures, bounded output, default-off detailed capture, encryption/privacy and linear durable-write counts at two run sizes. Do not claim full-run readiness from this integration alone.
5. Keep storage retention counts/bytes, supported crash/retry behavior and current limitations in maintained docs. Preserve all full-run requirements and current 900-page scripted baseline in CRS-170. Full CI on PR; independent review before deleting this ticket/index.
