# 🧰 CRS-213: Make supported backup and restore entrypoints unambiguous

Status: open. Unblocks [CRS-214](CRS-214.md). Serves the Operator's [operate and recover](../design/personas.md#operate-and-recover) job. This is entrypoint/error clarity, not a new backup format or old-schema migration.

## Evidence and boundary

`package.json` exposes `backup` and `restore`, but `src/server/recovery-cli.ts` describes its backup as a legacy plaintext portable operation. `profile-registry.ts` rejects the current encrypted registry format before that backup branch; this finding does not establish a plaintext leak or data destruction. The supported procedure instead copies a consistent complete encrypted archive, with recovery material separate ([deployment](../setup/deployment.md#backup-and-recovery)). The Operator should not have to infer this from an internal comment or generic registry error.

## Acceptance

1. Remove or clearly isolate unsupported public backup/restore aliases and document the supported encrypted-archive procedure through the normal npm → Compose setup/help path. Do not advertise the legacy portable CLI as an encrypted archive backup or Takeout export. Preserve useful current recovery internals and fictional tests; dead-code removal is not this slice.
2. Any retained directly callable legacy entrypoint explicitly refuses a current encrypted archive/package with a useful supported-procedure explanation before projecting plaintext or replacing a target. Unsupported formats remain unsupported; add no old-schema decoder, migration or automatic reset.
3. Fictional focused tests cover backup and restore refusal, invalid input and a nonempty destination. Original bytes, keyrings, manifests, accepted history and preexisting destination contents stay unchanged; no secret or health payload enters stdout/logs or a newly created backup. Distinguish incidental writer-lease metadata from medical authority in assertions.
4. Update maintained operations/help documentation and verify command discovery against current code. Run formatting, types, focused entrypoint/recovery tests and full PR CI; obtain an independent passing implementation grade before retirement.

No real archive, credential, recovery kit or provider is needed. This ticket does not certify an independent restore; CRS-214 owns that check.
