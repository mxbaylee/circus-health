# 🗃️ CRS-200: Keep the rebuildable record-history index compact

Status: open. Medium-effort, large-impact production prerequisite split from the storage investigation in pending [PR #35](https://github.com/mxbaylee/circus-health/pull/35). This slice changes the disposable SQLite history projection, not original files or immutable accepted-record authority. No older production schema support is required (owner decision).

## Evidence and boundary

After the incremental conversation journal landed, the dense 151-page scripted attempt filled its unchanged 1 GiB runtime with SQLite and its WAL before final grading. A separate fresh 12-page diagnostic run completed 44 requests/six slices/12 exact proposals with no acceptance or original mutation. Its WAL-aware database allocation was 6,524,928 bytes: `__record_versions` occupied 2,400,256 bytes and `__record_fields` 2,297,856 bytes. Source-file field history retained 571,660 before-value bytes and 870,818 after-value bytes across 290 rows, including repeated complete `details_json`, intake and workflow ancestor values. Fifteen source-file versions stored 279,732 content bytes plus 287,185 duplicate version-envelope bytes. These small-run measurements identify duplication; they do not establish the exact table shares of the failed large run.

`record-versions.ts` serializes every ancestor object while walking changed fields, persists before/after values for each ancestor, and stores both complete `contents_json` and a complete `version_json` envelope for each version. Keep each indexed version's contents once, retain small changed-path/reference metadata, and derive requested field values and version envelopes from the indexed immutable versions. Preserve existing public history semantics. The still-growing original intake workflow in durable source-file versions is separate CRS-201 work; encrypted whole-index publication is CRS-202 work. Do not claim that fixing this projection alone makes total durable storage linear.

## Acceptance

1. Remove duplicate complete version envelopes and repeated ancestor before/after JSON from newly built SQLite history indexes. Field-change records must contain bounded path/presence/version-reference metadata instead of copying entire subtrees. Preserve profile, entity, record, sequence, operation and predecessor identity, deletion state, ordering and indexed field filtering. Avoid introducing an equivalent growing snapshot in a receipt, cache row or journal.
2. Preserve the public history response exactly for supported current-format data: before/after values, absent versus null, nested `_json` fields, object replacement/deletion, arrays, literal invalid JSON, deletion/tombstones and stable pagination/filtering. Reconstruct only the selected page of requested history, never scan every version to answer one page. Profile/session authorization remains unchanged.
3. Keep originals and immutable accepted-record versions authoritative and unchanged. Version the disposable projection as needed; fresh indexing, normal restart and encrypted cache-loss rebuild must produce equivalent history/current records. An obsolete or malformed cache must not silently stand in for accepted authority. No old journal decoder or migration is required.
4. Add meaningful focused tests with hundreds of fictional edits to a growing structured value. Count SQLite allocated pages and indexed payload bytes at several sizes, distinguish one required version-content copy from bounded metadata, and prove repeated ancestor payloads/duplicate envelopes are absent. Verify exact history values, field filters, pagination, missing/corrupt references, isolation, transactions and cache-loss reconstruction. Do not reduce the input, alter medical values or prune historical evidence to pass.
5. Document the current history/index contract and measured scope. Run focused local tests/static checks, full PR CI and independent grading. Recheck affected storage with a small owned fictional run or equivalent real-intake mutation fixture; preserve the prior dense failure and retain CRS-201/202 plus broader capacity/diagnostic qualification. No new full 151/900-page run or capacity increase is needed solely for this projection slice.
