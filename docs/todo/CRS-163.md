## User Story

As an [Operator](../design/personas.md#operate-and-recover),
I want to know the household’s actual passkeys and recovery method can reopen the installation,
So that the people using it can regain access safely.

## Plain-English walkthrough

1. Open the hosted checker from CRS-226 in each browser I choose, follow the prompts and download its compatibility report.
2. Use a fresh fictional installation on the intended localhost desktop for the application checks the report cannot establish.
3. Enroll and approve repeated passkey unlocks on the actual browser and authenticator, then try recovery.
4. Recreate the containers and check retained access, adding and checking a second available passkey separately.

## Available automation

`npm run qualify:passkeys` runs an unmodified, headed installed Chrome or Edge on an exact HTTP localhost origin or an actual trusted HTTPS hostname, after the browser confirms a secure context. It refuses an installation with any existing profile, creates only a fictional profile, retains its recovery phrase in a mode-0600 external file, waits for real enrollment confirmation and three authenticator unlocks, switches from an active passkey attempt to recovery, verifies private access and locks the fictional profile. A bounded metadata receipt records only the observed progress and browser version. No virtual authenticator, credential override or TLS bypass exists in the production driver. See [physical qualification](../security/profile-encryption.md#physical-passkey-qualification).
