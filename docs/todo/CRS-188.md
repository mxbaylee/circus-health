# 🧮 CRS-188: Expose known retained-event omissions in diagnostics downloads

Status: open. Medium-effort, large-impact production prerequisite split from CRS-187. The current archive can report `available` after intact-prefix chunk eviction even though a retained cumulative checkpoint proves earlier persisted events are missing from the download.

## Requirements

1. Improve the existing profile-authorized diagnostics download and its browser explanation. Preserve the encrypted chunk format, bounded retention, recording policy and supported APIs; do not add another collector, qualification-only grader, storage migration or old-schema support.
2. For each window with a readable validated checkpoint, use its latest cumulative checkpoint once. Count distinct valid readable events and distinct exported events for that window, and expose the checkpointed persisted count and known persisted events absent from the download. The scope is only windows with retained readable checkpoints. Repeated checkpoints are never summed; global process sequence gaps cannot establish per-profile loss.
3. Mark the archive `partial` whenever its known persisted-event count exceeds the corresponding exported count, including intact-prefix eviction, invalid/unreadable chunks and export truncation. Retain existing failure/loss counters. The difference proves absence from this download; it must not invent whether the cause was eviction, corruption, read failure or export omission.
4. Entirely evicted windows, missing checkpoint history, history before retained inventory and an abrupt-shutdown tail remain unknown. A zero known difference does not prove complete collection or whole-run completeness. If first/last observation timestamps are exposed, derive them from actual events and never call them collection start.
5. Compute accounting during the existing bounded one-pass export. Reserve metadata inside the export byte budget so truncation cannot conceal its own accounting. Work and memory scale with retained chunks/events/windows, with no new durable writes or whole-document/profile copies. Keep yielding to foreground work. Lock/detach must discard protected export results including the new metadata.
6. Validate with independently fictional tests: real-store prefix eviction; unreadable/invalid chunks and invalid/duplicate events; output truncation; a completely evicted window; disabled recording after recovery; interleaved profiles using global event sequences; repeated checkpoints; and lock during export. Verify output bounds, incremental-write counts and profile isolation. Mounted/HTTP checks must show the normal download contains the accounting and accurately explains incomplete history.
7. Update maintained documentation with implemented meanings and limits. Run focused local tests, formatting/type checks, full PR CI and independent review. Delete this ticket/index entry on completion and preserve all unfinished CRS-187 requirements in a scoped remainder.

## Remaining work

Durable collection origin, pre-upload opt-in/readiness, run selection, full-size retention budgets, browser delivery/loss accounting, process/container recovery, the actual 900-page harness/baseline and early/late complaint reconstruction remain in CRS-187. Known window omissions alone do not qualify a full run or production readiness.
