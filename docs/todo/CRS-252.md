# 🗜️ CRS-252: Give pre-inventory ZIP plans a recovery path

Status: open; review finding from PR #71. An active ZIP plan saved before
inventory version 1 (or whose unit count no longer matches the inventory) makes
every paged package entry throw a plain error, so the import cannot be inspected,
read, re-planned or replaced. Compatibility preparation works for inventory-v1
plans only.

## User Story

As an [Operator](../design/personas.md#operate-and-recover),
I want an older ZIP import to either keep working after an update or tell me
clearly how to replace its reading plan,
So that an update never leaves a retained original stuck with no next step.

## Plain-English User Walkthrough

1. After updating, I open a ZIP import that was planned with an older version.
2. The app either shows its files as usual or explains that this plan must be
   rebuilt, keeping the original and accepted records unchanged.
3. I choose to rebuild the plan, and reading continues from a fresh plan with the
   cost of re-reading shown before it starts.

## Acceptance Criteria

### Scenario: An unsupported plan is refused with a usable reason

Given a fictional intake whose active ZIP plan lacks `index.inventoryVersion`,
When the package inventory route, member read, assistant package tool or plan
creation is called,
Then each returns the same explicit 409 code and message naming the replace action,
not an unclassified server error,
And the original, accepted records and other intakes are untouched.

### Scenario: The plan can be replaced without a legacy reader

Given the same intake,
When the person or operator chooses the replace action,
Then the old plan is superseded and a paged plan is created from the durable
inventory, leaving accepted records and the original unchanged,
And the work to replace is counted (inventory bytes hashed, plan records written)
and proportional to the package, with no model request until reading is resumed.

### Scenario: Release notes match behavior

Given the release-update instructions,
When they describe retained legacy ZIP sources,
Then they state which plan formats are prepared automatically and which need the
replace action.

  non-v2 plan.

  `src/server/assistant-intake-native.ts:118`; `src/server/intake.ts:6048`

- Base `b8a5a01` `src/server/intake-plan.ts:141-150` expanded ZIP members with or
  without `inventoryVersion`, so such plans can exist on installations updated

  refusal only; no route or replace-path test exists.

  prepared for paged responses, without this exception.
