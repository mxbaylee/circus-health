# CRS-118: Precise source dependencies

Status: open.

Pin interpretations to the evidence actually consumed: owned source pages/spans plus report headers, subject/date/units context, relationships and amendments. Final citations alone do not describe every dependency.

Appending unrelated source text must not stale existing work. Material changes must invalidate affected unaccepted proposals and approval state, including package relationships; unknown dependency coverage must invalidate conservatively. Preserve accepted history. Verify sibling publication, late responses, source corrections and acceptance races. This consolidates reliability R8 with the async processing requirements.

## Review findings, 2026-09-28 (R8)

Proposals are pinned to the whole source revision (`intake-source-text.ts:819`, `intake-source-text-dependencies.ts:35-62`, `intake-batches.ts:669`; test `intake-automatic-source-capture.test.ts:195`). Background capture of page 300 therefore stales proposals from page 2. Pin each proposal to the page hashes and context it consumed, and invalidate only those whose inputs changed. This is a prerequisite for [CRS-086](CRS-086.md): with revision-wide pins, sibling workers stale each other's work.

## Carried from the incremental-writes work, 2026-09-28

The intake's source pin (current material revision, dependency token, "requires interpretation" flag, revision count) now lives in its own record, `intake_source_pin:v1:<intake>` (`src/server/intake-source-pin.ts`), so a source change no longer rewrites the intake row with its proposals. Change what the pin records (the pages and context each proposal consumed), but keep it out of the intake row; moving it back would reintroduce per-write copies of every proposal. See [record versions](../data/record-version-storage.md#source-text-write-amplification).

[CRS-129](CRS-129.md) needs the same per-page consumption data to record source verification state separately from staleness; design the two together.
