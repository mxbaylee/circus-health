# 🧾 CRS-176: Count input composition on each physical model request

Status: open. Focused implementation slice of CRS-170, split before implementation because that investigation is high effort. This slice is medium effort, large impact and production-required. The remainder stays in CRS-170 until this slice lands, then moves to a new scoped remainder. This is diagnostic measurement, not a claim that the full-size import or diagnostics retention is qualified.

## Purpose and current boundary

The Operator needs to distinguish growing instructions, source/tool results and assistant tool arguments when a large import repeatedly fills model context. `proxyRequest` in `src/server/proxy-model-bridge.ts` currently retains total request bytes, media-part counts and structural counts per provider request, but not input composition. The optional private trace is not a substitute for ordinary content-free diagnostic metadata.

## Requirements

1. Add fixed numeric counts to the ordinary `model.request.started` observation for every physical proxy request, including retries and replacements. Reuse its unique provider request correlation. Measure the actual outbound body after compaction, rather than a logical turn's earlier transcript. Do not alter provider payloads, retries, fit limits or clinical behavior.
2. Count message totals, text UTF-16 code units and UTF-8 bytes for fixed system/developer/user/assistant/tool/other role buckets. Count assistant tool-call argument text and serialized tool definitions separately. Preserve total serialized request bytes and PDF/image counts; count media transport strings separately, including data-URL/base64 overhead and remote URL strings. Explain that these are transport/payload measurements, not decoded media sizes or token estimates. Text/category totals exclude JSON framing and need not add up to full request bytes.
3. Expose unsupported shapes and incomplete measurements explicitly; do not report an unsupported part as fully measured zero content. Never retain text, arguments, tool schemas, URLs, arbitrary role/key values, names, credentials or content fingerprints in these new fields. Use fixed allowlisted field names and bounded scalar metadata. Fit the normal event field cap even with private-trace linkage.
4. Disabled ordinary diagnostics must not perform the new composition measurement or change request behavior. Measurement failures must not break a request that would otherwise be sent. Keep measurement work proportional to the outbound request, and durable output a fixed set of counters per physical request, not copied payloads or corpus snapshots.
5. Test exact counts with independently fictional multibyte text, content arrays, tool arguments/results/schemas, PDF/image data and remote URLs, unsupported shapes, actual retry attempts and disabled diagnostics. Exercise the real recorder and encrypted archive/reopen/export path; all new fields survive, and privacy canaries do not. Preserve current request behavior and correlation.
6. Document field semantics, unknowns and bounded-retention limits in maintained import diagnostics guidance. Run formatting, type checking and focused tests locally, full CI on the PR, and independent review. Before closure, delete this ticket and index entry; carry CRS-170's unimplemented diagnostics readiness, scripted 900-page baseline and paid-route qualification requirements into a scoped remainder without claiming they passed.
