# 🧷 CRS-182: Reconcile large-import proposals against the literal oracle

Status: open. Medium-effort, large-impact production prerequisite split from CRS-181 before implementation. This slice is a pure read-only grader over actual proposal/review snapshots. Accepted public records, receipts and cache-loss recovery require a separate reconciliation slice.

## Purpose and current boundary

The fictional 900-page fixture supplies 901 expected assertions across two people and six reports, including a split table row. The existing single-person `QualificationRecord` envelope drops assigned-person and report-group authority; reusing it unchanged could hide wrong-owner or wrong-report results. An Operator needs separate evidence of clinical correctness, source attribution and resolved ownership before a completed import can be considered useful.

## Requirements

1. Consume the versioned large-import oracle and current `IntakeReview`, `IntakeReportQueueGroup` and identity snapshots using shared contracts. Require explicit distinct runtime People bindings for both fictional person keys and the retained original ID. Never infer runtime ownership from a marker, a label alone or a default Self mapping. Validate ambiguous/missing bindings and conflicting or duplicate authority snapshots conservatively.
2. Reconcile every expected assertion using exact supported labels. Report missing, unexpected and duplicate assertion matches, duplicate occurrence IDs and clinical field mismatches. Preserve literal signs, decimal precision, units and reference intervals, with canonical clinical classifications. Reject unexpected populated clinical fields; allow only narrowly documented host-derived values demonstrated by current server output. Keep work proportional to the snapshot and oracle rather than repeatedly searching the full corpus for every assertion.
3. Validate retained-original evidence using the existing exact page validator. Expected pages must be present as precise original-page locators; a broad range or another original cannot stand in for them. The split row requires both pages 149 and 150. Check record report-group references against real queue/identity snapshots, original source, printed report/subject anchors and expected report page boundaries. Label/date agreement alone is insufficient attribution. Occurrences legitimately retain the group version that introduced them; do not incorrectly require equality with the latest queue-header version.
4. Check mapping person ID, assigned person and evidenced name/DOB against the explicit bindings. Missing ownership remains unresolved; contradictory or wrong-person evidence fails. Return clearly separated clinical/provenance and ownership outcomes. Proposal-stage grading may identify correct clinical content while ownership remains unresolved; reviewed-readiness grading must require resolved nonblocking identity and review issues. No successful result is acceptance permission, extraction/collection completeness or end-to-end qualification.
5. Remain pure: no network, clinical mutations, identity confirmation, acceptance or durable writes. Reports should use fixture keys/counts and fixed mismatch categories rather than copying source documents or private payloads. Preserve missing information as unknown/failure, never an invented match.
6. Test full-oracle reconciliation and adversarial cases for missing/extra/duplicate records, unexpected fields, wrong original/page/report/person, missing split evidence, unresolved/conflicting identity, host-derived fields and valid older introducing-group versions. Include a small real upload→proposal→review fixture with independently written input envelopes, two saved People, all three clinical kinds and split evidence. Grade its actual returned snapshots against the full oracle and verify correct partial records plus remaining missing work; do not call that partial run a pass. Synthetic expected-record copies alone are insufficient validation. No full 900-page processing or provider inference is included.
7. Document the implemented API, input authority, outcome semantics and limitations. Run formatting, type checking and focused local tests; full CI on the PR and independent review before completion. Delete this ticket/index entry when it lands, and preserve all unfinished CRS-181 requirements and owner decisions in a scoped remainder.
