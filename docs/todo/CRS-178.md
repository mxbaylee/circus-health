# 🧮 CRS-178: Preserve known diagnostic archive losses across restart

Status: open. Medium-effort, large-impact production slice of CRS-177, allocated before implementation. The remaining qualification stays in CRS-177 until this slice lands, then moves to a new scoped remainder. No old-schema compatibility is required before production (owner, 2026-10-01).

## Observed defect and purpose

The Operator can recover retained diagnostic events after lock/restart, but `src/server/import-diagnostic-archive.ts` stores known dropped-event, oversized-event and write-failure counts only in memory. A fresh export's clean `currentWindow` therefore loses earlier known failures. Retained event availability is not enough to diagnose this loss. Persist bounded metadata checkpoints in the existing encrypted archive; this is not medical evidence or complete-run qualification.

## Requirements

1. Each newly published diagnostic chunk carries one fixed cumulative checkpoint for its archive window: observed, persisted, dropped and oversized event counts and write failures. A checkpoint describes the observed boundary when its bytes were built, not the end of a run. Persisted events include that chunk's payload only when publication succeeds. Export the latest retained valid checkpoint per window; never sum cumulative snapshots.
2. Freeze the entire envelope on its first publication attempt. An ambiguous published-then-thrown retry must use identical bytes and not duplicate events. Later drops/failures change live counters without changing frozen bytes. After retry succeeds, publish changed accounting through a bounded, coalesced checkpoint-only chunk if necessary. Oversized-only activity must also be flushable. Timer, explicit export and normal detach/close attempt publication; unchanged flush/export/close writes nothing. Persistent failures remain bounded and cannot alter clinical outcomes.
3. Use fixed safe scalar metadata. Validate nonnegative safe integer counters, conservative accounting inequalities and exact allowed envelope/checkpoint keys. Reject malformed/unsupported envelopes explicitly without exposing arbitrary fields or inventing zero measurements; no legacy decoder or destructive reset. Reserve envelope overhead within the existing 64-KiB plaintext bound.
4. Expose a bounded collection of latest retained window checkpoints during existing chunk reads, including its serialized size in the 24-MiB export budget. Known recovered dropped/oversized events or write failures keep status `partial` even if the new live window has no losses. Lock during export discards both events and checkpoints. Preserve profile/session authorization and recovery with capture disabled.
5. Keep `omittedBeforeInventory: null`, `crashTailEvents: null` and `completeness: not_established`. A retained checkpoint cannot count unpublished later failures or entirely evicted windows. A failed final publication remains unknown after restart, not proof of durable accounting. Collection-start/run scope and full-size retention remain unqualified.
6. Work scales with new chunks and fixed metadata: no reread/rewrite of earlier event payloads on ordinary append, no whole-document/profile snapshots, no chunk per dropped event. Test unchanged flushes and proportional 256/512-event write counts/bytes. An explicit ambiguous retry may reread its single retained chunk to verify equality.
7. Independently fictional tests must cover ambiguous publication plus four later drops surviving encrypted fresh reopen; oversized-only loss; successful and lost multi-chunk/multi-window recovery without cumulative double-counting; eviction/unknown history; malformed counters, extra/private keys and unsupported schema; lock interruption; output-budget truncation; persistent bounded failure; and unchanged flush/export/close. Exercise the normal authorized HTTP recovery/download contract and privacy canaries alongside archive tests.
8. Document implemented storage/export semantics and limits. Run formatting, type checking and focused local tests; full suite on PR CI and independent review. Delete this ticket/index entry on completion, and move CRS-177's remaining requirements and owner decisions to a new scoped remainder without claiming qualification passed.

## Scope boundary

Reuse the existing encrypted chunk store; its medical-authority separation and append/retention behavior remain intact. Full-run collection scope, browser evidence, measured retention budgets, early/late complaint reconstruction, the scripted 900-page oracle/baseline, foreground usability and adopted-route qualification remain in [CRS-177](CRS-177.md).
