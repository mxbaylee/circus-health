# 🎣 CRS-149: Stop assistant links from carrying data out, and prove sessions don't share an unlock

Status: open. Filed on 2026-09-30 after a read-only review asked whether a third party could pose as the model and pull data from an open session. No existing ticket covered it; `docs/todo` and `docs/security/model.md` were searched. Line numbers were checked at `1e6fa50`; re-verify before editing.

## Decision and why

The review found no way for someone else to pose as the model or ride an open session, so this is not a fix for a known hole. It closes the one remaining way out for data, and it adds a test for the session boundary that is currently established by reading the code only.

- **Privacy-sensitive patient:** an imported document is untrusted. Prompt injection ([security model](../security/model.md) R7) can steer the model's reads within the profile. Today the only way those reads leave the machine, other than to the configured provider, is a link the person clicks.
- **Caregiver:** opens several profiles on one machine, so they rely on each browser session unlocking only what it unlocked.

## Where it stands

- **The model channel is closed.** The LiteLLM proxy has no published port, sits on an `internal: true` Docker network, and requires the generated master key (`compose.yaml`). The app talks only to `http://litellm:4000`.
- **Unlock is per session.** `session()` in `src/server/vault-app.ts:71` issues a random 32-byte `circus-session` cookie (HttpOnly, SameSite=Strict) with no profiles unlocked. `requireAccess` returns 423 until that session unlocks the profile. The app port is bound to `127.0.0.1`. Hosts other than localhost are refused, and writes need the app's origin. No test has been found that asserts a second session cannot read a profile unlocked by the first.
- **External links.** `assistantLink` in `src/app/features/assistant/AssistantText.tsx:15` accepts any `http:`/`https:` URL without credentials and opens it in a new tab. A link such as `https://example.invalid/?d=<record values>` sends its query to that host when clicked. Images render as alt text and are never fetched.

## Requirements

1. Before opening an external link from assistant text, show its full destination host, and require a confirmation. When the link has a query string or fragment, say that it carries data and offer to open it without them.
2. Add the same rule to any other renderer of model-written text that allows external links. Check `NoteText.tsx`, which can hold model-proposed notes.
3. Add a server test showing that a new session, with no cookie or a different cookie, receives 423 for every profile route while another session holds the profile unlocked. The test should also show that locking revokes access for every session.
4. Update R7 and the assistant boundary section of `docs/security/model.md` with the result, as a detection and friction control, not a prevention control.

## Completion

Run the assistant, vault-app and mounted assistant-text tests plus the new session test. Obtain an independent passing grade before deleting this ticket, per `AGENTS.md`.
