# 🪡 CRS-225: Reconcile exact text snapshots with retained occurrence anchors

Status: open. Automatic snapshot-reconciliation algorithm split from high-effort CRS-218 before implementation on 2026-10-02. Builds on the implemented [explicit text-piece engine](../data/text-piece-edits.md); unblocks [CRS-219](CRS-219.md), which uses both primitives. No SQL, source-search replacement, production authority switch or model calls are in scope.

## User Story

As a [Records assembler](../design/personas.md#file-and-review),
I want to have the app keep unchanged document information when it notices changes,
So that I do not have to describe each small edit and my evidence stays accurate.

## Plain-English User Walkthrough

1. I provide an updated document and check the result.
2. Repeated passages and moved sections keep their correct place and meaning, while unchanged passages remain intact.

## Acceptance Criteria

### Scenario: Preserve contextual duplicate occurrences

Given old text is A,x,B,x,C,x,D with retained occurrence identities,
When automatic reconciliation receives x,A,x,B,x,C,D without caller-supplied edit intent,
Then the contextual occurrences remain stable and the unmatched final x moves with bounded boundary writes and no new content.

### Scenario: Keep a distant periodic middle unchanged

Given unique ends surround a long unchanged periodic middle,
When one character changes at each end or a prefix insertion and suffix deletion shift global boundaries,
Then automatic reconciliation preserves the unrelated middle content and occurrence links without a giant replacement or rechunk cascade.

### Scenario: Fail an exhausted automatic alignment

Given reconciliation exhausts its declared matching or work limits,
When the planner cannot establish a validated bounded edit result,
Then it fails explicitly rather than falling back to a full snapshot or treating hashes as positions.

### Engineer context

Equal text does not identify which occurrence moved; stable contextual reuse must be verified rather than assumed.

## Contract

A pure `reconcile(retainedSnapshot, nextExactText)` boundary derives validated explicit edits from old/new exact serialized text and prior occurrence anchors. Ordinary dirty-source storage must not require caller-supplied semantic intent or parsed operational intake views. Retained duplicate occurrences and moved blocks must keep stable identity where their unchanged context determines reuse.

## Detailed engineering requirements

1. Derive explicit text-piece edits from a coherent retained snapshot and next exact text, validating old head/anchors and the exact resulting string/UTF-8 bytes. Specify deterministic alignment and move/occurrence assignment. Retained-content token alignment followed by unmatched block reuse is a candidate, not a mandated algorithm; the required exactness/locality governs. Content hashes alone or global duplicate-content FIFO cannot establish position, and fresh global content-defined chunking alone cannot establish locality on periodic text.
2. Preserve distinct repeated occurrences through context/identity rather than silently replacing or exchanging unchanged anchors. Define a deterministic policy for genuinely ambiguous identical content. Qualify growing `A,x,B,x,C,x,...` adversaries: prepend another `x`, and separately move the final `x` to the prefix with identical content counts, such as `A,x,B,x,C,x,D` → `x,A,x,B,x,C,D`, scaled to increasing numbers of unique anchors. Unchanged unique-context occurrences and their unrelated links must remain stable, with only bounded boundary changes; a pure move writes no new content. Test increasing retained occurrence counts, not only fixed tiny examples.
3. Automatically handle tiny prefix/middle insertion/deletion, multiple distant edits, duplicate/periodic text, moves/reorders in both directions and maximum-piece boundaries. Preserve punctuation, whitespace, escape spellings, non-BMP characters and lone-surrogate escape spellings under the implemented engine’s declared offsets/text domain. Use independent exact-string/UTF-8 oracles and adversaries that shift fresh global chunk boundaries. Include a unique prefix and suffix around a huge byte-identical `ab` periodic middle: change one character at both distant ends, then separately insert one UTF-16 unit near the prefix and delete one near the suffix. Preserve every unrelated middle content/occurrence link through two local edits; no giant prefix/suffix middle replacement or fresh rechunk cascade is acceptable. Supplied-edit engine success alone does not satisfy these automatic cases.
4. Preserve the implemented engine’s bounded content/link/head and unchanged-row guarantees. Missing/corrupt/inconsistent retained snapshots, identity/anchor mismatch, invalid boundaries and exhausted limits fail explicitly. No full snapshot, giant replacement middle span for distant edits, growing occurrence array or silent global rebalance may serve as fallback when matching is difficult.
5. Measure initial cost and 100/200/300 actual automatic reconciliations, separately counting changed content/link bytes and rows, existing content rereads, snapshot matching/scanning/alignment, hashing, reconstruction and copied bytes. Declare and cap host matching/work budgets; full old/new comparison may remain linear or otherwise costly within the declared limits. Do not conceal that work as changed-only computation or use model-speed timing targets. Verify locality as unchanged payload and retained occurrence counts grow.
6. Publish a narrow tested TypeScript API usable by CRS-219 in its caller transaction, documenting deterministic reuse, complexity/limits, failures and measured scope. The return value is a transient plan of individually bounded changes, not another durable authority. No SQL schema, live source-list query replacement, production persistence cutover or real-mutation/large-import qualification is established here.

Use independently fictional data, no heavy imports and no inference. Reassess scope before implementation; split only at useful complexity boundaries. Completion requires focused automatic reconciliation/oracle tests, formatting/types, full PR CI and independent review; delete this ticket and its index entry only when implemented, preserving unresolved requirements and repointing dependents to maintained documentation.
