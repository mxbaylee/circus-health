# 🧩 CRS-201: Persist intake workflow changes without rewriting growing source versions

Status: open. High-effort production storage work split from the pending large-import capacity investigation. Follows CRS-200's compact history projection. Split into smaller implementation tickets before starting, or obtain owner grading before merge.

## Verified defect

`intake.ts` updates `source_files.details_json` with accumulated intake proposals, workflow, plans, candidates and groups. Small batch changes therefore version a growing original-source document through `record-versions.ts`. Reducing the disposable SQLite history index does not remove those repeated full source-row writes to immutable record storage. Originals and accepted medical records must remain durable evidence.

## Required design and acceptance

- Separate operational intake state into changed-content immutable contributions or bounded linked references committed atomically with the relevant source/profile transaction. Reuse existing source-pin separation, content-addressed source-text storage and transaction publication mechanisms where appropriate. Never replace full snapshots with growing reference lists or another whole-history journal.
- Preserve exact source identity, original downloads, proposal/candidate/group/operation/plan-unit status and version pins across restart, lock, interruption and encrypted cache loss. Public intake/review behavior, stale-review detection, idempotent operation replay and clinical acceptance authority must remain intact. Model output still requires review before acceptance.
- Define safe failure/retry ordering and strict profile/schema/reference validation. Do not simply omit workflow from durable records, infer missing history, discard medical evidence or let SQLite become recovery authority. No old-schema compatibility is required before production.
- Test hundreds of real batch mutations at multiple input sizes, counting durable changed bytes, objects, rereads and SQLite allocation. Prove work scales with changed evidence, and verify exact reconstructed pending state plus accepted-record/original invariants. Qualify interruption, failed publication, restart and cache loss before a heavy import recheck.
- Update maintained storage/intake/recovery contracts and the broader capacity investigation, run focused tests and PR CI, and obtain independent grading. Keep complete large-import diagnostic coverage and browser/adopted-route qualification open until independently evidenced.
