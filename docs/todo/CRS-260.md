# 🪓 CRS-260: Remove unreachable and parallel implementations left by PR #71

Status: open; PR #71 review finding. PR #71 moved most paths to native async
implementations but left their predecessors exported, tested and documented.
Tests exercising dead code give false coverage, and parallel implementations can
drift. Removal must not change any production path.

## User Story

As an [Operator](../design/personas.md#operate-and-recover),
I want the app to contain one maintained path for each storage and recovery job,
So that the checks protecting my records exercise the code that actually runs.

## Plain-English User Walkthrough

1. Nothing visible changes when I import, review, back up or restore.
2. The project's checks now cover only the paths the installed app uses.

## Acceptance Criteria

### Scenario: Unreachable code is removed with its tests and docs

Given a symbol listed below with no production caller at the closing head,
When it is removed,
Then tests that only exercised it are removed or moved to the live async path,
And maintained docs naming it are corrected in the same change.

### Scenario: Parallel implementations are consolidated

Given two or more implementations of the same grammar or reader,
When they are consolidated,
Then one implementation remains and existing exact-output tests pass on it,
And no limit, oracle assertion or refusal is weakened.

### Scenario: A listed item turns out to be live

Given an item whose reachability is not proven by grep alone,
When a production caller or route consumer is found,
Then it stays and is removed from this list with the evidence recorded.
