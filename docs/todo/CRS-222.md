# 🪴 CRS-222: Integrate target-bound intake in encrypted private copies

Status: open. Encrypted publication/retry integration split from high-effort CRS-208 before implementation on 2026-10-02. Builds on the implemented [unpublished-target bootstrap](../data/intake-state-storage.md#unpublished-target-bootstrap); unblocks [CRS-209](CRS-209.md) alongside CRS-220 and CRS-223. Production intake persistence remains unchanged until CRS-209.

## Contract

Integrate validated target preparation in `encrypted-profiles.open(copyState)` before initial accepted-record publication. Preserve the source archive and its authorization/session boundaries. Once a target accepted head exists, that selected target authority wins over a retry, a changed source or a later exception.

## Acceptance

1. Validate the currently authorized coherent source snapshot through the [bootstrap API](../data/intake-state-storage.md#unpublished-target-bootstrap) before owner/path or source-text changes. Transactionally rewrite destination ownership, retain existing source-text rebind semantics, drop copied source record projections and install target-bound intake evidence before first `attachPersonalDurability(recordStorage)` publication. Destination identities/references must match retained originals; verify actual retained original files and hashes. Never bypass readiness, publish source-bound intake evidence in the target or install another authority alongside it.
2. Preserve exact pending proposals/questions/plan units/decisions/stored intake and effective source-pin versions/pins/proposal-review identities/public acceptance and operation receipts and accepted clinical rows, modulo intentional profile/path/Self-display rebinding. Distinguish fresh internal bootstrap operations/replay namespaces from preserved public receipts. Preserve complete outer-envelope order, intake-slot position and nested exact normalized serialization. Untouched raw whitespace, duplicate-property spelling and escape spelling remain original durable/search bytes until an authorized rewrite or separately specified raw-text solution. Keep unrelated metadata and original bytes unchanged; destination mutations cannot affect the source.
3. Keep setup invisible and inactive until current recovery-verification/activation gates pass. If no accepted target head exists, a retry must obtain a currently authorized coherent source snapshot and prepare before publication; failed unpublished setup must remain invisible. If any accepted target head exists, including after publication followed by a throw or ambiguous flush, verify/retry/restart must recover that selected destination independently, without recopying an advanced source or requiring source re-unlock. Preserve published target authority and never reset it to make retry succeed.
4. Exercise the real encrypted copy path at source validation/preparation failure, immutable-write failure, immediately before first head, after publication but before completion/ambiguous flush and before activation. Prove no unpublished target visibility, preservation of already-published target evidence, correct retry selection and activation ordering. An exception is not a fabricated successful acknowledgement. Wrong profile/source/hash, missing/corrupt/unsupported evidence fails explicitly without borrowing keys or silently dropping pending scope.
5. Prove source archive/originals/accepted records remain unchanged, source/session authorization remains intact, and both profiles reopen, lock/unlock and rebuild after total cache loss independently without inference. Compare exact pending serialization, public receipt/pin state, accepted records and original hashes; exercise target mutation isolation. Reuse real encrypted-profile and source-text-vault fixtures with staged fictional incremental intake authority before production activation.
6. Document implemented publication and target-head retry behavior, with one-time preparation/copy costs and subsequent changed-evidence mutations. This integration does not close contributor-copy readiness, production source-authority cutover or real-mutation/large-import capacity qualification.

Use independently fictional data, no inference and no heavy import retry. Before implementation, reassess effort and split again if the boundary exceeds medium effort. Completion requires focused encrypted lifecycle/fault/recovery tests, formatting/types, full PR CI and independent grading; delete this ticket and its index entry only when implemented, preserving unmet requirements and repointing dependents to maintained documentation.
