# 🔐 CRS-202: Publish incremental encrypted workspace indexes

Status: open. Medium-effort, large-impact production storage prerequisite split from the pending large-import investigation. Independent of the SQLite projection and intake-authority fixes.

## Evidence and boundary

`vault-store.ts` publishes a new encrypted index containing the complete growing `files` and `objects` maps whenever workspace files change. Prior indexes are retained. The failed dense 151-page recheck retained 4,598 indexes totaling 3,914,790,639 bytes while 7,630 content objects totaled 6,374,480 bytes. A successful 12-page probe retained 378 indexes totaling 26,434,620 bytes versus 595,575 bytes in 627 content objects. Small manifest heads do not make these index writes incremental.

## Acceptance

1. Persist only changed file bindings and new object metadata per publication, using authenticated immutable index generations and bounded metadata. Keep the current small manifest commit atomic across the index tip and accepted `recordsHead`. Do not copy a growing map/reference table into each generation or delete evidence to claim lower growth.
2. Retain single-writer/profile authorization, object integrity/deduplication, private-file exclusions, staged workspace publication (`publishNow: false`), exact materialization, original preservation and backup/recovery semantics. Reconstruct once on cold open; hot writes must not replay the entire index history. Disposable decrypted maps must be cleared when the vault closes.
3. Explicitly validate identities, hashes/authentication, sequence/links, bounds and supported current format. Test failures before object staging, generation/head publication and ambiguous flush completion; never publish references to unavailable content or fabricate successful durability. No legacy schema decoder or migration is required.
4. Measure changed bytes/objects/rereads over hundreds of workspace updates at multiple sizes, including one changed binding after a large existing index. Verify reconstruction, cache-loss recovery, coherent backup, rejected cross-profile/corrupt content and failure retries. Keep originals/accepted authority unchanged.
5. Update maintained vault/security/storage contracts, run focused tests and full PR CI and obtain independent grading. Preserve SQLite/intake and diagnostic blockers separately; no runtime-limit increase or heavy known-failing import retry is part of this focused change.
