# ☁️ CRS-083: Private home/cloud deployment exploration

Status: open.

Assess local app/archive with a remote proxy and private hosted app/proxy placement. Preserve the supported npm → Compose → LiteLLM setup until another topology is implemented and verified. No hosting purchase or provisioning is implied.

Keep household admission, controlled enrollment, HTTPS/origin/passkey compatibility, credential isolation, restricted payload logging, cost/capacity limits and backup/restore explicit. Validate filesystem and provider behavior on the chosen host before making support claims. Hosted builds, secrets and ingress need the same review. Refresh capacity and pricing only when deployment is actually selected.

## Decision and why

**Hosting is decided by performance** (owner, 2026-09-30): if the app cannot run well on the owner's small laptop, it needs hosting; if it can, the supported local installation stays the answer. This is the Operator's need in [CRS-130](CRS-130.md): someone who runs the app on a small laptop and pays for AI reading. Reachability matters too: an app on a closed laptop is unreachable, which limits [CRS-145](CRS-145.md)'s emergency-contact access.

## Measure first

Measure the laptop in counts, per `AGENTS.md`, never with a pass/fail bound in seconds for model work. On one representative long fictional import run on the laptop, record:

- Model requests, retries and bytes or tokens sent per page, and pages read per slice.
- Local extraction work: raster and OCR pages, extraction-step timeouts and watchdog retries, and queued units.
- Whether interactive requests stay answered while the import runs, with any host timing only as a coarse ratio against an idle baseline on the same machine ([CRS-109](readme.md#crs-109)).
- Peak memory and swap or CPU-throttle counts, if the host reports them.

Two changes could move the answer, so measure them the same way:

- Async/background processing with bounded context ([CRS-086](CRS-086.md)): fewer bytes resent per request and work that continues in the background.
- Trying the Bifrost gateway instead of LiteLLM, now one option in [CRS-089](CRS-089.md) (a lighter, less patched gateway): added requests, retries and bytes per model request, plus what a replacement must reproduce: the stream-semantics patch (`deploy/litellm/patch_chatgpt_stream_semantics.py`) and the native-PDF behavior `deploy/litellm/test_native_pdf.py` checks. This is an experiment; the supported setup stays npm → Compose → LiteLLM unless another gateway is implemented and verified.

A dated measurement is evidence about one setup, not a target. [CRS-110](readme.md#crs-110) (a separate processing service) uses the same evidence.
