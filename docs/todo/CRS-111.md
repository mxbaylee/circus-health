# CRS-111: Early identity evidence for person assignment

Status: open.

Detect printed patient names and birth dates from available original evidence, separating patients from subscribers, guardians, guarantors and contacts. A mismatch never stops reading; offer Self, an existing person or a new person, with explicit report-scoped assignment before acceptance. Other-person records stay outside Self trends.

An ambiguous DOB must ask rather than silently pass. Model hints may prompt review but cannot establish an original-grounded match. Require original evidence for automatic matching and preserve cache consistency. Check an existing person's DOB when assigning; avoid unsafe single-name aliases and ambiguous duplicate-name choices.

Retain supported confirmed names without overwriting primary name or DOB. Preserve uncertainty and report boundaries; provide an evidence-scoped repair path when contradictory source claims prevent forming a valid assignment scope. Verify bulk acceptance cannot hide an unresolved identity decision. Former reliability feedback R12–R18 informs this item; accepted-record reassignment is CRS-119.

## Owner decision

[CRS-126 D1](CRS-126.md#d1-records-for-other-people-are-welcome): records for other people are welcome. A mismatch asks who the report belongs to and never rejects or stops reading.

Two-digit birth years (owner decision 2026-09-29): still ask, but prefill the inferred four-digit year for the person to confirm or change. Infer the latest century that puts the birth date on or before the report's date, or today's date when the report is undated. The prefilled year is a suggestion, never evidence: it does not count as an original-grounded match until confirmed.

Name-only matches (owner decision 2026-09-29): a report matched on printed name with no printed birth date keeps its automatic assignment and stays in **Select all**, but its person control reads differently from a name-and-birth-date match: "Jordan Rivera (you?) · Review" instead of "(you) · Change", with the accessible label saying Review too. The same mark applies when the name-only match is an existing person rather than Self. A person's own confirmation (`prior_confirmation`) keeps the plain form. The signal belongs where the person already looks, not in the bulk action.

## Current behavior verified in review

Before acceptance, the report header's **Change** / **Review** control (`ImportReviewPresentation.tsx:988`) reassigns the report's pending records. A missing birth date with a matching name gives `evidenced_match`, which shows "(you) · Change" and is treated as confirmed (`ImportPage.tsx:752`); the person can change it before accepting. The collection-page `PersonFilter` only filters the view. Accepted records cannot be moved; see [CRS-119](CRS-119.md).
