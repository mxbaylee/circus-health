# 🪞 CRS-161: Review historical raw assertion ownership in the app

Status: open. UI/release remainder of CRS-156. Depends on CRS-160's durable preview/commit contract.

## Requirements

1. Offer a discoverable profile-private review path from the packet omission notice and retained Sources evidence. List unresolved assertions in bounded pages; the packet itself keeps a nonidentifying generic disclosure. Reuse SourceRecordView/SourcePreview and People choices rather than a parallel source renderer.
2. Show the retained original, exact assertion locator and proposed Self/managed Person assignment together. Require explicit review before accepted changes; no default to Self and no silent whole-file assignment. Mixed-family exports and conflicting decisions need assertion-scoped choices. Explain that person assignment does not certify clinical content or imply provider amendment.
3. Use CRS-160's pinned preview and stable operation IDs. Keep unresolved changes visible through interrupted saves; stale source/person state requires a refreshed preview and fresh confirmation. Private operations stay profile scoped and session authorized.
4. Test mounted accessibility/keyboard and narrow-layout behavior plus an encrypted browser journey on an independently fictional older archive. Cover Self, managed Person, clinician mentions, conflicting decisions and mixed-family source files. After review, render the correct person's packet and evidence companion, then repeat after cache-loss rebuild. The generic notice disappears only when no eligible ambiguous assertions remain; inspect nonidentifying behavior for other people's packets.
5. Update maintained user/import/storage/packet guidance with the supported restoration path and limits. This remains a production requirement even after the backend lands.

Complete with independent review, focused local checks and full CI; delete ticket/index and preserve any unfinished requirements in a new scoped item.
