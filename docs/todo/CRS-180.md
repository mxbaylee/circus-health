# 🧪 CRS-180: Create a fictional 900-page clinical fixture and literal oracle

Status: open. Medium-effort, large-impact production prerequisite split from CRS-179 before implementation. This slice supplies reusable test input and expectations; normal upload, scripted provider behavior, review/acceptance and full-run qualification remain in the investigation remainder. No paid inference or private records are required.

## Purpose and evidence

The existing host benchmark can stream many pages but has no clinical correctness oracle. The live qualification fixture supports one Self patient and at most 100 mixed pages. Increasing that scenario length would exceed its date formula and retain incorrect single-person/page grading assumptions. The Operator needs independently fictional known-content inputs to distinguish completed processing from correct records and ownership in the current 900-page baseline.

## Requirements

1. Generate exactly 900 pages as six 150-page reports, alternating two explicitly fictional people and native-text/raster-only pages. Print report and subject headers, valid fixed per-report dates and literal supported observation, medication-order and performed-procedure facts. Use no real records or copied patient data.
2. Include a genuinely split table row within one report: its clinical label is printed on one page, its result/unit/reference on the following page, without either page repeating the complete assertion. Preserve explicit report/person attribution, both original page numbers and per-field printed origins in the oracle. A repeated table header alone does not meet this requirement.
3. Define a versioned literal oracle with fictional person/report keys and unique assertion keys, using existing shared clinical mapping types. Preserve exact values, signs, precision and absent fields. Owner keys are independent of runtime IDs and Self; neither PDF nor oracle grants acceptance authority or chooses the runtime owner. Do not send the oracle as model instructions. Future reconciliation must exercise normal People and identity review.
4. Reuse the benchmark's streaming PDF mechanics through a shared bounded page writer and preserve the existing benchmark API, vectors, scan-only behavior, hash and explicit benchmark padding. Hold only one page's content/image at a time, plus bounded page-offset metadata; do not assemble the whole PDF in memory. The new clinical fixture has no artificial target-size padding. Return actual bytes/hash and native/scan/page/expected-record counts; do not claim 15-MB/115-MB representativeness or pipeline qualification.
5. Write generated PDF/oracle files only to caller-provided test/output locations outside Git, with exclusive creation and private permissions. Fail safely on output conflicts and clean up this operation's partial outputs without deleting preexisting files. Provide a small reusable API for later harness work, not a new deployment or paid-provider path.
6. Focused tests generate the actual 900-page PDF in a temporary directory, verify bytes/hash and real PDF page count, inspect selected native pages across report boundaries and near the end for literal data, and prove selected scan pages have image operators and no hidden text layer. Validate oracle coverage, unique keys, both owners, kinds, valid dates and the split row's distinct origins. Verify both split-page descriptions through a small native rendering as well as the real mixed fixture. Verify writing bounds/conflicts/permissions and retain existing benchmark tests. Rendering/layout must keep the intended text visible; PDF-only checks do not establish OCR accuracy.
7. Document the implemented generator, oracle semantics and limits, with artifacts outside Git. Run formatting, type checking and focused local tests, full CI on the PR, and independent review before completion. Delete this ticket/index entry when it lands and preserve all unfinished CRS-179 requirements and owner decisions in a new scoped remainder.
