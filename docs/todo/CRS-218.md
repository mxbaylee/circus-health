# 🪢 CRS-218: Prove local serialized-text piece edits

Status: open. Pure algorithm prerequisite split from CRS-207. Independent of CRS-217's durable order implementation; unblocks CRS-219. Inputs are exact serialized text and retained prior piece/occurrence anchors, not parsed operational intake views. No live source-search or persistence switch in this slice.

## Acceptance

1. Define bounded content pieces, stable occurrence identities and a small selected head, with validated splice/move operations. Small changes must not rewrite unchanged content or serialize a growing occurrence/reference list into one record. Retain prior anchors or derive validated local edits; fresh global content-defined chunking alone does not establish locality on periodic text.
2. Reconstruct exact input bytes, including punctuation, whitespace, escaped Unicode, non-BMP characters and lone-surrogate escape spellings; define UTF-16 versus UTF-8 offsets and validate boundaries. Unknown/inconsistent edits or malformed piece chains fail explicitly. Repeated equal pieces remain distinct occurrences; content hashes do not establish position.
3. Test a tiny prefix insertion/deletion, middle insertion/deletion, multiple distant edits, duplicate/periodic text, max-size piece boundaries, reorder/moves and multibyte/surrogate boundaries. Use an independent exact-string oracle and adversarial fixtures that would shift global chunk boundaries. Bound each piece/link write and show small local changes leave unrelated content/links unchanged.
4. Measure initial cost and 100/200/300 updates: changed content/link bytes and rows, existing content rereads, scan/diff/reconstruction work and copied bytes separately. Full input comparison may still cost linear host work; do not conceal it as changed-only computation. A full snapshot, giant replacement middle span for distant changes or rewritten occurrence array is not a fallback.
5. Publish a narrow tested TypeScript primitive for CRS-219, with explicit limits, complexity and failure contracts. It must not add a parallel recovery authority or SQL schema. Run focused tests, formatting/types, full PR CI and independent review; document only the implemented primitive and carry unresolved integration into CRS-219/220.

Reassess and split before implementation if medium effort no longer fits. No heavy imports or model calls.
